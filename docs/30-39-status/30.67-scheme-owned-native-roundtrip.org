#+title: Scheme-owned native numeric round trip
#+options: toc:nil num:nil

* Evidence and architectural decision

Predecessor =330658b= passed all six supported checks in
[[https://github.com/tao3k/gerbil-scheme-rust/actions/runs/39899722557][its exact-head CI run]]; the unsupported SMP job was skipped.
The standard Gerbil -> Gambit -> C -> native module compiler chain remains
unchanged, including dynamic-module optimization level 2.

[[file:30.66-coupled-owner-refill.org][30.66]] corrected refill arbitration but did not demonstrate an overall
performance improvement. Its CPU throughput fell 0.68%, mixed throughput rose
0.51%, and both short native p99 values worsened. Construction tails remained
roughly 0.38/0.43 ms despite microsecond medians. That experiment remains intact.
The earlier aggregate mixed throughput regression and these tails have not been
attributed uniquely to allocation, GC, native task execution or OS runnable delay.

The next protocol boundary is ownership between native construction and service
admission. PipelineCycle built the entire numeric payload/header/envelope,
published a temporary external root, returned through Rust, and called the
Scheme endpoint again. Native input creation and publication into the Scheme
job graph were separate foreign entries, although the same owner performs both.
Projection additionally pinned, sized and copied each numeric child through
separate foreign entries. The completed protocol addresses both boundaries.

The new explicit capability lets Scheme construct/copy the original payload and
admit it through the original Actor service in one foreign entry. Only the
identity receipt crosses back to Rust. This removes a temporary input root,
the service-header/outer-envelope objects and the intervening foreign return.
The same numeric payload builder, scheduler, work ledger and result retirement
remain authoritative. Static removal of these operations is not itself a
throughput or GC claim; matched measurements are reported below.

Input-buffer pooling is deliberately excluded from this protocol. Complete
Scheme handlers may retain or alias their inputs; reusing a vector merely
because its request completed could mutate an escaped value. Every request
still receives fresh Scheme input vectors copied from its owned Rust data.
There is no new restriction on Scheme input retention or execution capability.

* Explicit Scheme and Rust capabilities

The standard endpoint must explicitly permit native admission. Its sixth
optional argument defaults to false, preserving custom command wrappers:

#+begin_src scheme
(make-gerbil-rs-service-endpoint handler workers on-open on-prepare on-close #t)
#+end_src

Applications that wrap the command endpoint must audit that native submission
preserves their command-1 behavior before granting this capability. It is not
inferred from a symbol name, payload shape or the existence of a native export.
Unmodified endpoints reject capability acquisition. The qualification enables
it only for the real orders endpoint, whose submit path needs no outer wrapper
hook. The single-worker wrapper remains unmodified and explicitly rejects it.

#+begin_src rust
dispatcher
    .configure_scheme_service_completion_on(owner, SchemeServiceCompletion::PipelineCycle)?
    .wait(timeout)?;
assert!(dispatcher
    .configure_scheme_service_native_entry_on(owner, true)?
    .wait(timeout)?);
// Existing typed request, stream and pool APIs perform the actual submission.
#+end_src

Service ABI 12 adds command 19 for an idle PipelineCycle endpoint. It returns a
Scheme closure bound to that endpoint's service lifetime. The owner retains it
inside the existing checked root arena; Rust receives no Scheme pointer and no
new global registry. Acquisition checks the advertised service ABI and optional
image-local =gerbil_scheme_rust_numeric_service_enter= export plus the complete
optional native numeric snapshot/copy ABI. Non-idle or
non-opted-in endpoints reject it. Repeated enable is idempotent. Disable and any
completion-policy change revoke its root. Closing stops/drains the original
service before final owner-arena release. No ordinary default changes.

=NativeSession::scheme_service_native_entry_enabled= reports only capability
presence. It exposes no root identity, raw procedure or cross-owner authority.

* Typed admission, projection and failure ownership

=SchemeServiceRequest::enter_service= returns an opaque owner-local
=SchemeServiceSubmission=, distinct from an ordinary =NativeRoot= payload.
Only =SchemeServiceInput::submit= or =enter_numeric= can create this receipt;
safe application code cannot manufacture an admitted identity from an input
vector. Checked/routed wrappers forward the new hook and keep their snapped
lane, class and work declarations. The default hook uses the original arbitrary
=construct_service= and endpoint call. Generic Scheme types, GC, continuations
and custom construction therefore retain their existing execution path.

The built-in numeric request uses =enter_numeric= for input and a private
numeric child snapshot for output when the explicit capability is enabled. Without the capability it
uses the existing fused construction plus ordinary submit. With the capability,
it calls the shared native batch builder and the Scheme submission closure
without publishing the temporary input graph through the external root table.
Header metadata is validated and passed directly; rows are still copied with
the existing sealed numeric layouts. Rust spans live through the synchronous
native copy/admission only. No pointer is retained by Scheme.

Both paths charge the same cumulative input budget, including the original
header/outer-vector charge even when those temporary objects are eliminated.
Quota rejection occurs before the entry attempt marker. The marker is set at
the foreign-entry fence and survives exceptions/unwind independently of the
returned receipt. An uncertain failed submission is drained by the existing
owner failure path instead of retried as unentered work. Native exceptions use
the original bounded diagnostic-string contract; exception graphs are not kept.

=NativeSession::numeric_batch_snapshot<T>= returns an owner-local
=NativeNumericSnapshot<T>=. One native entry copies the selected child identities
into a private vector and reads all sizes; Rust then validates cumulative output
bytes with checked arithmetic and allocates initialized buffers. One further
native entry revalidates kind/count/sizes before copying through the existing
nonallocating numeric-span leaf. Counts remain bounded to 1..=256. No Scheme
body pointer crosses or survives the foreign frame.

The private vector pins all selected children across Rust allocation and GC,
including after the original parent/root is released. Removing per-row roots
without this snapshot would be unsafe for a mutable parent. The snapshot fixes
row identities, not application-owned numeric contents; it does not freeze or
reuse user data. Generic per-element projection remains available for custom
Scheme projections. Each completed request still clears its own result slot,
roots and capacity before the next request retires. The snapshot is a lexical
temporary root, not another persistent arena allowance.

| Lifetime boundary | Rule |
|-------------------+------|
| Rust preparation | One bounded owned input per owner, cancellable and without a new Scheme root |
| Entry fence | Original accepting/cancellation/deadline/close checks; declared slot/work reservations remain held |
| Construction | Fresh native payload, reachable on Scheme's stack during allocation and GC |
| Submission | Original service lock validates lane/class/capacity and publishes the input into its job graph |
| Receipt | Only the identity becomes an external temporary root, projected on the same owner |
| Completion | Existing native batch slots, per-result root release and capacity retirement |
| Capability revoke | Remove only the owner's capability; do not refund or move accepted request resources |
| Close | Join accepted Scheme work, release internal/application arena roots, then native cleanup |

There is one bounded capability root per enabled owner, separate from the one
completion-snapshot arena root. Neither consumes the 65,536 application-root
allowance. Rollback and final arena cleanup include both internal roles; a
failed configuration reply cannot leave a newly acquired capability behind.
This is necessary lifetime retention while enabled, not an input cache. It must
be zero after successful revoke/owner cleanup.

Rust continues to distribute across fixed complete Scheme runtimes. Actors,
green threads, cooperative execution budgets, continuations and GC stay in
Scheme. No SMP, Rust translation of Scheme, alternate interpreter or JSON
transport is introduced. Dispatch budgets still do not preempt arbitrary Scheme
constructors or guarantee an elapsed-time SLO.

* Native and model evidence

Native tests cover nine numeric families (including extrema, finite floats and
empty rows), wrong kind/count rejection, parent-root release followed by GC and
snapshot copy, narrow output quota followed by a healthy generic request,
cancellation/expiry/close at the three-ready-result frontier,
exact input quota and one byte below, repeated acquisition and revocation,
configuration-reply abandonment, all 65,536 application roots plus native
submission/result retirement, Scheme failure followed by a healthy request,
and zero-root/image-file cleanup. The four-VM suite enables the capability on
one owner while exercising generic native types, GC, continuations, exceptions
and recovery. Other endpoint configurations retain their previous path.

The existing lifecycle model adds an owner capability set, acquisition/revocation
and the original prepared-entry fence under that capability. Completion-domain
witnesses cover use, cancellation/close cleanup and revocation without releasing
a prepared request's reservation. Sampled pipeline scenarios and all existing
negative controls remain wired. This finite model checks ownership/accounting;
it does not prove C/FFI correctness, native GC safety or elapsed-time fairness.

inside that run. The experiments have different frozen source/image identities;
their percentages must not be chained or treated as an isolated cross-run A/B.

* Decision and validation

Keep the complete numeric round trip as an explicit experiment. The CPU path
shows a measured gain; mixed short-request isolation is still incomplete.
Snapshot and all ordinary defaults remain unchanged. The next protocol question
is how a short request's admission/entry boundary interacts with the complete
Scheme-owned service cycle, rather than another bulk window or wake threshold.
The current data do not uniquely attribute the mixed tail to OS scheduling,
allocation or GC, and pooled stage quantiles must not be subtracted for that claim.

- Final unobserved native integration: 3/3, 32.16 seconds; controller 44.64
  seconds including compilation. The separate sampled diagnostic passes but
  does not substitute for this unobserved receipt.
- Reused focused Quint: pass, 146.50 seconds test / 151.76 seconds controller;
  ten required counterexamples retained. Three new capability witnesses run in
  both completion domains. This remains separate from native C/GC acceptance.
- Qualification Clippy with warnings denied passes, as do isolated-only Clippy
  and harness Clippy. Documentation/style/checked-conversion development
  failures are retained and corrected without suppressions.
- O2 benchmark build passes. Generated Scheme regeneration and update-disabled
  whole-file verification pass. Existing metadata receipt tests remain wired.
- The native test first exposed an obsolete zero-root assertion: the enabled
  capability is one necessary root. It is now accounted exactly, while revoke
  and successful cleanup must still reach zero. This failure is retained.
- The standalone Cargo-path watchdog launch and earlier native exit 70 remain
  separate unresolved records. Neither is converted into native acceptance by
  a model pass, an immutable-copy control or a later favorable sample.

All detailed logs, captures, executable copies, stack samples and source archives
remain local. No private absolute path or raw artifact is required by the
maintained reproduction command above.
