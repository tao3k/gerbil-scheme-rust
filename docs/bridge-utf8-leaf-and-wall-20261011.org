* Official source audit

The matching local Gambit source under the Gerbil SDK source checkout is used;
no compiler download or rebuild is required.

- =lib/c_intf.c:2795-2855=: foreign-pointer conversion checks tags and reads the
  pointer field without allocating, calling Scheme, or collecting garbage.
- =include/gambit.h.in:10325-10378=: the generated =c-lambda= route uses CFUN
  framing and an out-of-line selection. Its overhead is distinct from scalar
  encoding work.
- The actual generated encoder passes the =(void*)= tag list. Passing =#f=
  instead would accept unrelated typed pointers; it is not an equivalent fast
  path. A new bounded static sentinel verifies rejection of an =int*= foreign
  pointer without modifying its bytes, for both baseline and candidate.
- =lib/_kernel.scm:3999-4056= and =lib/mem.c:359-370,7683-7697=: process statistics
  include GC CPU in total CPU. Allocation accounting includes Scheme heap and
  stack consumption, not malloc calls or retained Rust capacity.

* Full baseline attribution

=just bridge-utf8-matched --costs= completed with exit zero. Each of seven
phases has 20 samples at each of 1,000, 10,000, and 100,000 requests: 420 raw
rows, with no missing or truncated rows in
[[file:benchmarks/20261011-utf8-leaf-cost-attribution.log][the complete receipt]].
The earlier prototype's transport-truncated capture is explicitly non-admitted
in [[file:benchmarks/20261011-utf8-leaf-cost-partial.log][the partial receipt]];
it is not used to fill gaps in the full run.

The new dispatch control uses the production fixnum chunk arithmetic and the
actual private encoder wrapper. Each of the fourteen bounded leaves receives
an empty span, while pointer conversion and bounds checks remain active. The
destination canary must remain unchanged. This control includes its own outer
entry, loop, and GC: it is not an exact subtractable price for a production leaf.

The owner-thread CPU counter uses the OS =CLOCK_THREAD_CPUTIME_ID= directly from
C, without an additional Scheme callback. Each row records signed wall minus
thread CPU; tiny negative residuals reflect snapshot boundaries and are not
clamped. Unavailable counters or a major page fault reject the diagnostic.

GC does not explain most of the observed wall time. Even the GC-free Rust
validation phase has a median per-row non-CPU residual of 576.279 ms. Process
and owner-thread CPU approximately agree. Owned transfers record a median of
3,856 involuntary switches. A read-only host snapshot found 1,324 processes,
91 runnable, and 1,114.8% aggregate CPU utilization. This supports scheduling
contention as an important contributor, but does not identify every blocking
cause or assign all delay to one external application. No processes are stopped.

CPU work scales approximately with load; wall time does not under this shared
host's changing contention. Lower GC counters alone cannot admit an optimization.
The non-null empty-leaf control also differs from the null-pointer empty-entry
floor, so neither is subtracted to manufacture an encoder-only throughput claim.

* Memory and optimization decision

For this corpus, each Rust result contains 8,196 bytes and reserves 13,660 bytes.
The extra 5,464 bytes are spare capacity, not an RSS measurement. The allocation
phase is not the dominant CPU cost. A second exact-size scan or default shrinking
adds work and cannot be justified by a lower capacity number alone.

The candidate keeps the scalar algorithm, capacity policy, 256-character bound,
pointer-tag checks, interrupt boundary, and complete output validation unchanged.
It uses =##c-code= with the official allocation-free pointer converter to avoid
the private =c-lambda= CFUN framing. The complete source-only experiment is saved
in [[file:benchmarks/20261011-utf8-checked-inline-leaf.patch][the replayable patch]].
Its source base is the pre-audit PR head =7d172c9487c53c8d3544ca3ae945ceed50f20920=;
reverse-apply validation against the candidate succeeds without changing files.

Admission requires full same-process ABBA testing: twenty samples per variant
at each load, full Unicode/surrogate/mutation/bounds/root/pointer contracts, and
no paired wall-time regression. The diagnostic table is not a substitute gate.

All three paired wall medians satisfy the unchanged no-regression gate.
The CPU reduction is modest; at 100,000, GC CPU is 17.802 versus 17.500 ms and

not a stable isolated-host speedup promise. CPU does not replace wall admission.

=just bridge-regenerate= (exit zero), without rebuilding the installed SDK.
