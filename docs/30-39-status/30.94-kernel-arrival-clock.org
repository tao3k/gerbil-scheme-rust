#+TITLE: Planned arrival, kernel clock observation and bounded native admission
#+STARTUP: overview

* Contract gap

The existing workload plans 64 short arrivals at 500 microsecond intervals from
one release Instant. Tokio Sleep has millisecond granularity. A requested
sub-millisecond plan therefore does not imply a sub-millisecond timer service.
The rejected client-turn capture is retained; changing bulk client polling did
not solve its mixed client p99. This is evidence to fix the arrival contract,
not proof that the timer explains every native or OS tail.

Planned arrival, timer observation, actual issue, bounded queue publication,
owner claim, native completion and client consumption remain distinct. Neither
a timer event nor an issue token owns a native permit or Scheme root. The
original planned-issued-native-consumed-v3 partition and its denominators stay
unchanged, including serial backlog. The serial probe source is unchanged.
An absolute planned arrival is not a promise that the source can issue while
its preceding request still awaits consumption.

* Actual opt-in API

The arrival-clock Cargo feature enables InstanceArrivalClock and
InstanceArrival::wait_with_clock. The clock uses an exclusively borrowed,
reusable, single-shot Darwin kqueue timer registered with the current Tokio
I/O reactor. NOTE_NSECONDS expresses the remaining duration without rounding
to milliseconds. Each wait arms a timer even for an overdue plan; it never
skips a timer, busy-waits, creates a thread or changes worker priority/leeway.
Nanosecond input units are not a nanosecond OS scheduling guarantee. A late
observation remains visible in the original deadline-resume component.

InstanceArrivalWake exposes planned, arm_started, armed, observed and generation.
Issue is recorded after observation and timer teardown. The original deadline
is preserved; no wall-clock conversion is used. Timer consumption uses a zero
kernel timeout, clears stale reactor readiness on WouldBlock and validates the
returned generation. A cancellation guard disarms the timer. Reuse arms a new
generation. Dropping the clock closes its owned descriptor. Kernel errors and
overflow fail explicitly; they do not silently issue or fall back to Sleep.

The first backend supports macOS only; other hosts return Unsupported. Creating
a clock requires a Tokio runtime with I/O enabled; like AsyncFd, an entered
runtime with its I/O driver disabled panics. No-runtime creation returns an
error. Existing tokio-dispatch feature selection and public defaults do not
enable this backend or its additional reactor dependencies.

The actual native test carries the issue token into the existing short-pool
submit_progress/wait_observed API. Pending Rust input is bounded by the pool,
while native credits begin only at owner claim. A cancelled timer never enters
that pool; a dropped/expired unclaimed ticket refunds its slot. Claimed work
still retires on its fixed Scheme owner. Scheme execution, GC, Actor/green
threads, continuations and exception ownership are unchanged.

* Joint model and controls

The existing owner lifecycle/runtime model gains clock generation, pending
event and observed state. Observation grants neither issue nor admission.
Directed witnesses cover future/overdue arrival, cancellation and reuse,
producer-aware close, early/stale-event mutations and direct-admission mutation.
Generation is finitely bounded in the model; it does not prove real OS latency.
Previously rejected model fixture runs are preserved: the first lacked pool
producer registration; the second tried to join registered producers before
finishing them. Neither failure was repaired by weakening safety properties.

The first real clock run failed all three tests at reactor registration with
EINVAL, before any Scheme call. Tokio AsyncFd::new requests both read and write
interest, whereas Darwin only accepts EVFILT_READ for a nested kqueue. The
implementation now uses explicit READABLE interest; the failed run is retained.
This is a reactor registration fix, not a timer or latency pass.

Executable controls exercise real timer events, stale readiness, cancellation,
duration overflow, descriptor release and actual bounded short-pool submission
behind blocked native owners. The full native lifecycle suite retains its
five-second meaningful-progress watchdog. The historical first-port watchdog
failure remains unattributed and its original cleanup unverified; a fresh pass
does not explain it. New binaries, source identities and images are frozen
before native execution so any recurrence can be attributed.

* Matched performance qualification

Use the standard O2 Rust bench with the explicit arrival-clock feature and
=--progress-fair-ab --fixed-short-selective --arrival-clock-ab=.
Both arms share four live native VMs, two Tokio workers, batch eight, work 32,
window four, Actor quantum one, NativeBudget, retirement-before-send,
ready-owner bulk delivery and the unified short observer. Both use independent
Tokio clients. The only selected difference is unconditional Tokio Sleep versus
an unconditional kernel timer for the same original arrival plan. Clock setup,
arming, observation, teardown and trace assembly are measured costs. The timer
fd is allocated inside the measured probe future. The control retains Sleep.

Qualification uses five ordered and reversed CPU/mixed blocks. There is no
expanded matrix. Every window must retain the same 8192 bulk orders, 64 short
plans, native-work oracle, roots, budgets and cleanup, with no compiler present
at either capture boundary. Candidate windows must contain 64 real armed timer
generations; no overdue timer bypass is accepted. The original client total,
native p99, throughput and owner spread are reported with negative results.
Performance acceptance is separate from model and native correctness. No
candidate is committed or promoted merely because its model or tests pass.

The corrected arrival timing also changes when contention occurs even though
the planned load and native work are identical. The capture measures that net
effect; it does not isolate syscall cost as the cause of the throughput loss.

This candidate is REJECTED for performance. Keep it explicitly opt-in for
reproducible diagnosis; no public default, commit or push changes. Do not run
the unchanged candidate again to select favorable windows. The next protocol
work must address actual native admission/entry and completed-result client
service opportunities together, without retaining native credit/root ownership
until client consumption or repeating the rejected client-turn-only shortcut.
The clock contract is necessary but is not end-to-end fairness acceptance.
The original first-port watchdog remains unattributed; this passing capture
and native suite do not replace its missing failed-image/phase/stack evidence.
