The optional implementation moves
bounded independent input supply onto the existing fixed owner. Scheme retains
execution, Actors, green threads, continuations, exceptions, timers and GC.
Rust supplies owned typed payloads and distributes work across instances; it
does not select or replace Scheme green-thread execution. Native Scheme/C O2,
the SDK, all library defaults and existing five-second native gates are unchanged.

* Actual API and admission contract

The input count is nonzero and at most the existing native queue capacity.
Every original work/lane/execution/trace declaration is frozen before awaiting
registration. Declared work is nonzero, each request fits its captured native
work budget, and aggregate staged work fits the explicit stream bound. Active
requests have a separate positive bound no greater than that same capacity
object's immutable slot limit. It is not inferred from a racing free-slot count.
An equal-numbered capacity reconfiguration is still a different epoch.

These are count and application-declared work bounds, not an exact byte bound
for arbitrary Rust values. Application-owned Rust payload retention is explicit;
constructed native payloads/results retain the existing transfer limits. Work
units are not CPU-time predictions. The stream accepts explicitly independent
requests without an Actor lane. Dependent/affine requests keep their existing
owner-pinned APIs and full Scheme semantics.

Poll registration and =next= inside a Tokio runtime with its time driver enabled.
The fixed native owner itself does not run a Tokio executor.

Registration reuses the existing per-owner producer semaphore, inbox publication
and close/epoch fence. Numeric producers and service producers cannot register
concurrently on one owner. Staging acquires neither a native request slot nor
Scheme roots. Each supplied request separately acquires an active-stream credit
and the existing native work/request pair, rechecks cancellation, deadline and
owner epoch/close state, then commits to the original typed Scheme service job.
The owner checks its ordinary inbox between supply turns; queued short work
retains the existing path into Scheme's short queue. Sustained external inbox
traffic is not an unconditional producer-liveness guarantee.

The accepted path remains =TypedJob::start=, Scheme's native asynchronous service,
and =TypedJob::complete= through the common native execution/root-balance path.
No new Scheme command or alternate payload representation is introduced. Scheme
chooses actual Actor/green-thread execution and cooperative class grants.

* Cancellation, expiry and drain

- =cancel()= and dropping the stream reject only unadmitted staged work.
  =InstanceError::Cancelled= names that outcome. Cancellation after the final
  admission fence cannot retract a committed entry even before construction.
- Registration and all later admission attempts share one absolute deadline.
  Timing out =next()= consumes that delivery observation, not the accepted task.
  Entered Scheme is never preempted or migrated.
- Cancelling a pending acquisition drops its partial work/slot future and active
  credit. Returning partial internal Tokio work allocations uses the original
  capacity-return notification protocol.
- The producer registration stays held until all committed jobs have completed
  native projection/root balance and returned their active credits. Rejected
  staged requests do not release a registration that still owns accepted work.
- Once only accepted work remains, the producer exposes no admission deadline.
  The owner waits on the native Scheme event instead of repeatedly polling an
  expired deadline. Positive finite waits are rounded up to microseconds, never
  down to the ABI's zero/infinite sentinel; overflow saturates positively. A
  separate unit control covers sub-microsecond and maximum finite durations.
  Completed work returns its semaphore credit; the owner pump
  observes final drain directly without an additional explicit self-notification.
- The public handle holds only a weak reference to its cancellation signal.
  Keeping a fully consumed handle retains no wake descriptor/image through that
  signal. Unconsumed application outputs keep their ordinary resource ownership.

* Matched native workload

The exclusive =--resident-ab= Rust bench uses the same four VMs and image, two
Tokio workers, original input/owner partition, 8,192 native 48-line orders, batches
of eight, and 64 native four-line short probes. Both arms use general batch
service plus native short service, native port wake, cooperative budget one,
feed one, coalesced notifications, four request slots and 32 work units per owner.
No OS priority is changed. Bulk owner placement is fixed in both arms; short
routing uses the same explicit reselection router in both. This avoids treating
an owner-routing change as a supply improvement.

The control uses the existing host-refilled service API with three bulk credits
per owner and the 128-ticket flow ceiling. The candidate uses the new public API
with three active requests per owner and at most 32 staged batches per owner,
256 staged work units each. Both retain the original host input corpus; this is
not a claim of identical Rust peak memory. Candidate staging and control ticket
retention are distinct scopes, each explicitly bounded. Each original typed
constructor, Scheme handler, payload, output projection and final result position
is unchanged. FIFO result observation is retained. The experiment measures the
complete supply mechanism, not an isolated primitive or an OS-free latency.

Startup/configuration are outside timing. Ten samples per arm/load alternate
AB/BA. Actual and serial nominal-500-us scheduled short latency remain distinct;
the probe driver is not a fixed open-loop arrival process. All negative rows
and all probe-overlap/fairness observations must be retained. No default is
promoted from this experiment.

* Protocol model

The existing =owner_lifecycle.qnt= is extended, not duplicated. A producer's
active limit is separate from pool slots/work. Normal and reserved admission
check it. Open-state cancellation removes only staged work and its reservations;
accepted Scheme roots/credits remain until ready/take/completion and final
producer retirement. Deterministic scenarios cover window reuse, cancellation
with accepted graphs and an active-window bypass mutation. The sampled stream
step and targeted mutation are wired into the existing Rust model driver.
Partial semaphore implementation, weak descriptor lifetime, native construction,
GC, continuations, actual shutdown and OS timing remain native obligations.


* Native closure and model controls

The final nine semaphore/pipe/finite-wait controls pass (0.05 seconds execution).
The existing ordinary numeric producer fixture passes (2.89 seconds), and the
extended four-VM Scheme service fixture passes (5.83 seconds), using unchanged
five-second native progress/request gates. These execution times exclude builds.
The fixture includes:

- Active-window saturation and an actual short result while two Scheme batches
  are suspended and further producer work is staged.
- Cancelled registration wait, explicit staged cancellation, absolute admission
  expiry, consumed delivery timeout and dropped stream handles. Accepted graphs
  remain live and drain before the producer registration returns.
- A native partial-work acquisition: four ordinary jobs hold 25 work units and
  all request slots; a producer awaiting eight internally holds the remaining
  seven. Cancellation refunds all seven before the ordinary jobs complete.
- No expired-deadline busy loop while accepted Scheme work is suspended, checked
  with the existing native Advance counter rather than a speed threshold.
- Native GC, constructor/projection panic controls, a Scheme exception and an
  independent successful successor through the common typed path. Existing
  continuation/affinity and initialization-failure cases remain in the fixture.
- Close with both accepted and staged producer work: accepted results complete,
  staged work returns Closed, four owners join, roots balance, copied files are
  removed and descriptors return. A fully consumed stream handle is deliberately
  kept alive across the final FD count to qualify its weak cancellation signal.

Both focused Clippy gates pass with warnings denied. The exact new dev-profile
CI smoke and the final release/phase smoke each produce eight valid rows and
clean native shutdown. No new jobs, matrix or watchdog change: the existing native
CI job adds the resident smoke and runs =instances::= core controls, including

Quint typecheck and 35 existing/extended small scenarios pass. The sampled stream

all saved time was kernel wake overhead.

* Admission decision and remaining gap

The bounded native supply API, cancellation/backpressure/deadline/close protocol
and the directed native controls are implemented. The observed CPU and mixed
throughput gains justify retaining this explicit experiment. Defaults remain
unchanged; tail/fairness and industrial performance acceptance remain open.
RSS convergence and universal image unloading are not re-certified here.

The short router accounts for its routed requests; directly staged bulk work
also has native budgets and an active window but does not become that router's
bulk ledger. Both arms deliberately share that limitation. A free native credit
still does not identify a promptly runnable owner. Fixed staged placement can
also leave fast owners finished while other owners retain independent backlog.
These are concrete next integration boundaries for producer progress, short
owner selection and pooled independent supply, not evidence for raising priority,
weakening Scheme semantics or changing the default algorithm. Reuse this baseline
and the current model/native protocol; do not expand the thread matrix or restore
the rejected wait-phase hint to conceal the remaining tails.
