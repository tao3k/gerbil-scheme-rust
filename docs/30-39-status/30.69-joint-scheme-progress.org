* Admission decision

This is an explicit experiment. Snapshot remains the default. Neither the
withdrawn payload shortcut nor this protocol is admitted for publication until
the matched performance comparison passes. Negative captures remain immutable.
Rust distributes owned inputs across fixed owners. Scheme retains its complete
runtime, cooperative scheduling, Actor state, continuations and collector.

The preceding payload-shortcut comparison is a rejected experiment: mixed short
p99 +158.099%, mixed throughput -0.351%, with material scheduled/admission stalls.
Its local commit was archived and removed from the publication branch. Its
shortcut symbol, Rust API and benchmark path are removed from current code.
It is not the control arm of the new comparison. Both new arms instead use the
previous complete numeric native round trip and original short submission path.

* Existing evidence and the actual protocol gap

The seven largest mixed candidate requests in the earlier native-roundtrip
capture spent only 1.583--3.750 us constructing and 0.834--1.208 us projecting;
their pending intervals were 410.709--506.375 us. Reducing short payload FFI did
not resolve the dominant interval. The subsequent rejected shortcut capture
also had substantial scheduled and admission excursions, without same-spike
blocked/runnable/GC evidence. Neither capture establishes collector causality.

There is a concrete source-level gap independent of that unproven attribution:
=service-ready-ids!= skips its scheduling yield whenever any bulk result is
ready. A newly submitted short request can still be awaiting its first Scheme
worker dispatch. The completion fast path has no explicit record that this
scheduler opportunity is owed. Separate class queues and ready epochs alone
do not encode that obligation.

* Joint protocol

** Ownership and transitions

1. The ordinary submit function records an =awaiting-start= bit on a short job
   only when joint progress is explicitly enabled. The Scheme service increments
   its pending-dispatch count before publishing the job to an idle worker or
   queue. Rust input preparation, native roots, request slots and work budgets
   keep their existing ownership rules.
2. Before native readiness harvest or native event wait, if a short dispatch is
   still pending and there is no ready short result, Scheme offers one scheduler
   checkpoint. A ready bulk result does not suppress it. The checkpoint neither
   clears the obligation nor waits for arbitrary handler completion. No new
   time threshold, retry window or polling timer is introduced.
3. The actual worker clears the job bit and decrements the pending count exactly
   once, immediately before entering the original handler. It records a worker
   start and signals the existing Scheme condition; the condition waiter must
   recheck actionable work. It does not write a native host wake byte.
   A notification, host observation, yield or Rust cancellation cannot fabricate
   this acknowledgement.
4. A ready short result is harvested immediately using the existing short-first
   readiness path. The existing completion epoch/token and result-slot custody
   remain intact. Every result independently releases its root and capacity
   after projection, before new native bulk construction.
5. Pre-entry cancellation introduces no dispatch obligation. Post-entry timeout,
   abandoned reply and close retain Scheme ownership until acknowledgement and
   completion/drain. Close verifies no dispatch obligations remain; it cannot
   silently erase a pending counter and report clean shutdown.
6. Changing completion policy disables joint progress. Explicit configuration
   requires an idle PipelineCycle endpoint without a held ready token. Default
   configuration introduces no additional scheduler yield.

The new state is Scheme-local, constant-sized apart from one bit per already
bounded native job. There is no additional global root registry, Rust green
scheduler, recycled mutable input graph, or cross-VM Scheme-object movement.
The existing port remains a coalesced host-actionable level: result readiness,
external Rust input and control transitions publish native wake bytes. Worker
acknowledgement is internal progress, so it cannot make an empty native result
wait return to Rust. The condition-variable transport already rechecks its
ready/input predicates after a signal; the refined native-port behavior preserves
that distinction. Readiness remains durable in the original queues.

** API and limits

Service ABI 13 adds idle configure command 20 and readback command 21. Older
supported services remain usable; only the new methods require version 13.

- =configure_scheme_service_joint_progress_on(owner, enabled)= opts in explicitly.
- =scheme_service_joint_progress_on(owner)= returns actual Scheme enablement,
  outstanding dispatches, scheduler checkpoints and acknowledged worker starts.

A checkpoint is a scheduling opportunity, not a hard wall-clock bound or proof
that a short handler has completed a cooperative unit. Arbitrary noncooperative
user code, collector pauses and OS descheduling remain possible. Handler
exceptions and continuation behavior retain their original Scheme semantics.
The five-second meaningful-progress watchdog is unchanged.

* Reused Runtime model

The existing =service_sharing= refinement gains a pending-dispatch set, an
owner checkpoint receipt and a joint-policy bit. Short publication creates the
obligation; =ackDispatch= is a separate real-worker transition. Short computation
cannot precede that acknowledgement. Bulk harvest without a checkpoint while
short dispatch is pending is rejected. Ready short work must be included first.
An empty harvest consumes the old checkpoint, and new short publication cannot
reuse a stale checkpoint receipt. Existing transient input roots, GC/OS gates,
ready epochs, per-result credits and close/join rules remain authoritative.

New small/wide witnesses exercise persistent debt after yield, actual dispatch
acknowledgement, short completion and independent retirement, timeout/close drain,
and the bypass mutation. Acknowledgement alone leaves the host wake level
unchanged; result publication sets it. The wait witness fails if internal
acknowledgement is accidentally treated as an actionable native wake. The sampled joint-policy lane reuses the same resource
step and invariant. The mutation must produce a counterexample. This model does
not predict p99 or simulate the exact Gambit runnable queue.

* Native validation

The normal native test exercises real short requests, handler exception and

Pipeline preparation/cancellation/timeout/close fixtures also enable the joint

The probe client is serial: it waits for each response before issuing the next
request relative to a fixed 500-us schedule. =actual= ends at the owner's native
completion timestamp; =scheduled= includes lateness relative to the planned
issue time, but neither includes a separately measured client-consumer wake
interval. =post_admission_wait= is a saturated difference between owner entry
and the client's admission receipt: it can be zero because they overlap, and is
not an exclusive owner-queue duration. These definitions are unchanged in both
arms; no end-to-end client-delivery SLO or GC attribution is inferred.

The publication decision requires throughput, tail latency and fairness together;
a model pass, fewer FFI calls or a single improved percentage cannot admit the
candidate. All negative short/bulk tails, scheduled/admission stalls and owner
imbalance are retained. No favorable rerun or expanded matrix replaces a failed
capture. The 120-second capture limit and native watchdog are unchanged.

* Next architecture question from the existing source

The order handler acquires one cooperative service unit around an entire order.
The fixed corpus has 48 line records per bulk order, whereas a short input is
truncated to 4 records; both still acquire one service unit. The progress ledger
also reports stable completed item identities, not an independently bounded
amount of native CPU work. A logical unit therefore does not imply comparable
execution cost or a wall-clock bound.

This is a concrete type/protocol distinction for the next refinement: request
slot capacity, reserved work/progress accounting, actual execution opportunity
and completed-result retirement are different authorities. The current change
makes dispatch acknowledgement and host-actionable wake distinct, but cannot
turn a coarse cooperative unit into bounded native execution. Any next design
must preserve original admission charges and same-load semantics, reuse the
current ledger/model and retain full Scheme continuation behavior. Changing
only a quantum, reducing FFI calls, or attributing all tails to GC would not
close this gap. The corpus difference is not proven to cause the measured
outliers; historical watchdog attribution and stable performance remain open.
