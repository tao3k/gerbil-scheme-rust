#+title: Mailbox counterexample coverage and evidence boundaries

* Scope and unchanged references

This audit consolidates retained failures before any new runtime candidate. It
changes models and their check entrypoint only. It does not run a performance
benchmark, modify the SDK or production path, relax the 128 backlog limit, or
certify the cause of a natural watchdog failure.

The retained 7F 5M/s row delivered about 1.003M/s and had 3,943.455 ms p99 and
4,000,404 peak debt. Offered rate is not delivered capacity.

The existing research gate's example admission profile remains 418,000 ns p99,
128 peak debt and 3,000,000,000 ns whole-run time. This audit does not introduce
a new runtime threshold or reinterpret that profile as a certificate for the
10-second 6D replay. Each historical replay retains its original workload and
deadline; the shorter whole-run gate is an admission profile, not a replay timeout.

* Corrected model defects

The previous gate allowed outcomes with no binding to the planned population,
run, image, entry route or main phase. It could accept a negative peak sentinel,
and it trusted a candidate-supplied failure set and limit argument. Those were
actual defects in the acceptance model, not evidence that the runtime suffered
every corresponding failure.

=mailbox_measurement_contract.qnt= now owns the evidence types, count and
quantile consistency, main-run binding, explicit histogram upper rounding,
conservative peak uncertainty and the last-planned-arrival lower bound. Counts
are mutually exclusive terminal outcomes; incomplete populations cannot be
reported as full-population p99. These consistency checks do not independently
recompute a real histogram or prove that a receipt is truthful.

=mailbox_research_gate.qnt= consumes retained research state. A candidate cannot
supply an empty known-failure list, ratchet either reference, expand admission
limits or substitute a small component's valid outcome for the main workload.
New failures feed the next decision. Rollback removes runtime candidates while
preserving references and the union of learned factors. Qualified repair and
evidence labels still require external source/VM/measurement receipts.

=mailbox_resource_contract.qnt= separates zero roots, full cleanup, unload
eligibility, classified image retention, long-term convergence and process-tree
build monitoring. A sampled RSS peak is not an enforced maximum; a signal alone
is not proof of OOM. Cleanup error -73 cannot be waived by an exited owner.

=actor_service_calculus.qnt= separates logical transfers from actual green-thread
dispatch changes. Existing two-transfer/two-dispatch algebra keeps its values,
but it is now an explicit scenario. Packing, resume and observation costs must
be included. Abstract ticks are not measured nanoseconds.

* Verification and limits

Run =just mailbox-research-gate-check= from the repository root. It checks
measurement (17), resource (9), cost-refinement (3), research-admission (28) and
layout-entry trial (11) and existing aggregate (295) cases with the TypeScript backend and fixed seed.
These suite counts overlap through aggregate imports and must not be added as
a count of distinct modeled runtime failures.

The audit also removes individual constraints in isolated copies and requires
an actual assertion violation (QNT508), not a parse/type/backend failure. This
checks that the new guards have executable witnesses, including a positive
admission example; it does not prove arbitrary real executions satisfy them.

Still unknown: the exclusive GC CPU cost in a natural gap, blocked versus
runnable waiting in that same gap, long-term RSS convergence of the candidate,
and whether a proposed whole-cycle change improves the frozen workload. Old
summary maxima, a successful fixture or a missing reproduction cannot close
those questions. No new runtime cause or performance gain is claimed here.
