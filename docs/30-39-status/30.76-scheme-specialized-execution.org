* Execution protocol
Rust distributes native typed jobs to fixed owner threads. Complete Scheme
execution, Actor scheduling, suspension, continuations and exceptions stay in
Scheme. ABI20 uses the existing item ownership protocol without an outer turn
lease. It specializes the execution plan, rather than changing fairness bounds.

A VM budget stores three shared class-specific acquire/release hooks. A bounded
latest layout-cache entry stores immutable whole/sliced plans. Hooks capture only
the budget, never a handler, normal-return flag, invocation record or Scheme root.
The existing acquisition mutex copies permission into the current owner's grant
state. Initial entry reads that permission once inside the wind body, constructs
cold metadata under that existing ownership, selects and reports a plan, then
executes application Scheme code. VM setup includes the shared three-hook vector;
it is not an allocation-free initialization claim. Both arms share that setup. The selected plan is
a lexical binding in the captured continuation. Replay reacquires ownership in
the shared before hook and resumes the retained suffix without selecting or
reporting again. Successful whole returns accrue their declaration; exceptions
reach no terminal credit site. Release/suspension settles existing work exactly
once. Sliced checkpoints retain their class, epoch and owner checks.

The fixed-shape =with-gerbil-rs-service-work-layout= macro puts known Scheme
application code directly in the wind body. It removes an intermediate handler
wrapper closure and indirect callback from the specialized path. The ordinary
function API remains valid and uses the same plan protocol. Public lexical entry
validates the layout before typed cache access. Other policies reuse already-read
context through the existing dispatch body, avoiding duplicate validation/context
reads in the matched control. A forged-layout control must reject before grants. Necessary wind entry/exit callbacks remain: they
protect arbitrary continuation exits, reentry and exceptions.

* Ownership and invalidation
- Permission is current-owner grant state, not a transferable invocation lease.
- Selected immutable plans survive nested execution, suspension and multishot
  replay. Later class obligations affect future selections, not retained spans.
- Policy replacement invalidates accounting through identity fences. Old
  continuations retain Scheme execution but cannot credit the new epoch.
- The cache retains one latest entry; saved continuations intentionally retain
  their old metadata. No per-thread unbounded callback table is introduced.
- Logical-work credit cannot release a native root, result token or admission
  capacity. Cancellation, timeout and accepted-close draining keep those existing
  independent authorities and owner-local retirement rules.
- A selected span bounds cooperative declared work, not arbitrary instruction
  time. Scheme handlers must honor their declarations/checkpoints; foreign or
  noncooperative code cannot be preempted by this protocol.
