* Reuse the lifecycle model

=specs/owner_lifecycle.qnt= adds =service_sharing=, importing the existing lifecycle
as =life=. Admission, assigned owners, work/slot credits, native roots, completion,
timeout, close and join retain one authority. No duplicate lifetime model is added.
The two finite domains use two single-processor VMs, two persistent Scheme workers
per VM, and four/five requests; these are exploration parameters.

The refinement separates host inbox/native entry, class queues, assigned workers,
one VM execution resource, cooperative work, blocked/woken tasks, VM-wide GC, OS
pause/resume, completion projection and draining. Abstract delay ticks are not
milliseconds. OS and collector progress are external assumptions; arbitrary
Scheme handlers need not yield.

** Executable counterexamples and candidate rules

- Queue separation can leave a short request behind an executing native turn.
- A reserved short worker still shares the VM CPU with a runnable bulk worker.
- GC blocks both classes on the same VM. A stateless short request assigned to a
  different VM can complete while the bulk VM is collecting.
- An OS pause defeats a deadline derived only from queue state.
- Bounded eager feeding removes a modeled avoidable entry gap without discarding
  accepted roots. Abandonment and close still retain them until completion.
- A separate candidate cooperative CPU lease bounds one abstract work unit, then
  uses class debt so eligible bulk work follows short execution. With one short
  reservation per modeled owner, an eligible short worker is overtaken by at most
  one new bulk lease. This is not a wall-clock or starvation-freedom theorem.

The candidate CPU lease/class debt is model-only. It is not implemented as a
preemptor, nor silently attributed to the existing Scheme worker algorithm.
Current-policy checks explicitly omit those assumptions and cover cooperating
class-routed callers with opt-in feed two in the finite domain, not the default
feed-one configuration or arbitrary independent producers. Fixed Actor/session
ownership cannot be migrated to get the stateless routing benefit.

The complete existing Rust gate passed in 355.76 seconds: 79 scenario runs,
6,000 sampled traces of at most 64 steps and 12 deliberate mutation controls.
Each mutation requires exit 1 and an actual invariant violation; parser/tool
failures do not count. Both current and candidate shared-resource policies were
sampled on both domains. Finite simulation is not an unbounded proof, a GC
implementation check, a scheduler fairness proof or a performance result.

* Actual opt-in algorithm change

=configure_scheme_service_feed_on(owner, maximum)= validates open service,
configured slots/work/producer state and an idle capacity boundary. The bound
must be positive and fit native slots. The default stays one.

The owner publishes up to that many immediately available FIFO service inputs
before advancing Scheme. It never waits to fill a batch. Non-service input ends
the feed at the existing FIFO boundary. Scheme alone chooses Actor/green-thread
execution; accepted permits stay held through native projection/root retirement.
This targets a host-entry gap, not VM-wide GC, arbitrary handler preemption or a
pool-wide isolated short lane.

For the slowest 1% of individual probes, pre-construction spans account for

native spans account for 39.2%/41.4%. These paired per-request fractions are not
subtractions of aggregate p99. They show that feeding changes where delay appears;
they do not isolate pure OS wake time or establish a single root cause.

** Independent observed feed capture

The separate instrumented feed pair also completed 40 samples and clean teardown.
Across ten samples per arm and all owners, CPU advance calls fell from 20,482 to
11,621; mixed fell from 18,921 to 13,518. Both arms submitted and retired exactly
10,880 jobs per load. This confirms fewer host advancement boundaries, not higher
throughput admission. Mixed native-wait wall totals rose from 18.845 to 20.896
seconds, while submit wall totals rose from 1.158 to 1.682 seconds. Spans overlap
CPU/GC and sum across owners; they cannot isolate pure wait or OS cost. The model's
entry-gap rule removes one transition cost but leaves VM execution/GC sharing.

* Next decision boundary

Bounded feeding must earn its own throughput/p99/fairness result. Even a positive
capture cannot establish the stronger cooperative Scheme CPU rule. Implementing
that rule requires a real Scheme yield/service boundary and native validation
without weakening arbitrary macros, continuations, exceptions or GC. Stateless
owner partitioning is another explicit capacity trade-off; it cannot move live
Actor/session state. Defaults remain unchanged pending reproducible evidence.
