#+title: Whole-cycle layout-entry trial and current-control review

* Disposition

The isolated prototype is withdrawn from runtime consideration. The research
checkout's Scheme runtime files remain at 7f915df; no candidate macro was applied
to them. Its source, complete image and failed evidence remain archived. No
performance improvement, root cause or solution to the 128 peak limit is claimed.
The withdrawn runtime prototype is not committed. Only the models, check
entrypoint and evidence records are published. SDK, policies, defaults, deadlines and queue/frame sizes
are unchanged. No 5M trial follows this failed 1M admission.

This is a completed code-level trial, not merely a design proposal. The candidate
was constructed, compiled, linked, checked in a real VM and exercised once under
the original workload. It is not a new accepted baseline.

* Source-bound proposal and complete cost

The actual frozen 7F expanded Actor source has SHA-256
=6991ff02e36115023fb68ded532abc9daf4e335024eb78aa6815b57c0131e283=;
its C source is =c60af2b2bc021f3a11bcc072400c80aba27fe3e03e6c16deb6ad3b9afa432868=.
Parsed definitions confirm that only =orders-handler/rank= changes among 437
definitions. The proposed source change is in the existing lexical work-layout
macro, selecting its no-work branch before generic layout dispatch. The measured
prototype is a corresponding refinement of frozen expanded Scheme; it is not
claimed to be an untouched frozen image or an independently regenerated whole
source graph.

The original no-work path allocates one closure capturing three business values,
then the generic dispatcher allocates another capturing thunk and declared cost.
The prototype uses one closure capturing four values and still calls the ORIGINAL
=call-with-gerbil-rs-service-unit=. Context reread, acquisition/release, exceptions,
suspension and multishot dynamic extents remain owned by that existing API.
Active work policies retain their original branches. No new queue, sleep/wake
registration, Actor topology or per-message clock/observation is introduced.

cannot be called executed poll counts. The full call chain includes the original

real, but is not a quantified net CPU or GC benefit and cannot bound future pauses.
No-work/empty-plan specialization must not bypass a live budget's unit gate.
The earlier empty-context proposal was inspected separately: that proposal tried
to avoid service-unit, whereas this trial retains it.

Gambit's complete linker-info block is identical (52,347 bytes), permitting reuse

common input hashes are rechecked. The budget-module C used for static inspection
is byte-identical to the control object cohort's C; an adjacent prefix alone was
not trusted as evidence. Existing loader dependency IDs match between images.
A stale OpenSSL link search directory was replaced with its existing stable opt
path without modifying or substituting the SDK or dynamic-library install IDs.

- GCC O2 Actor-object observed process-tree peak: 845,594,624 bytes. The separate

  the original 8 GiB monitor limit, with zero remaining owned RSS on exit. A
  sampled peak is not an enforced kernel maximum. Compiler optimization-disabled
  warnings are retained; no optimization level, memory cap or tuning parameter

- One initial macro build could not find the SDK's baked-in runner GSC path;

  recorded independently from real VM evidence.

* What the evidence permits next

At a due-but-unconsumed peak D, at most three requests own published frames.
Therefore unpublished source debt is at least D-3 at that cut. This is a bound,
not subtraction of unrelated observed maxima. The current lower bounds are
228,451 and 405,234. Most debt is not physically queued mailbox payloads;
adding another result FIFO or simply creating more Actors cannot by itself
supply the missing source progress.

The full period must gain actual consumption opportunities AND spare service
capacity. Preserved source eligibility, oracle and true frame return must remain
charged. Fewer closures do not establish either an arrival/pause envelope or an
individual-request fairness bound. The existing feasibility contract owns those
obligations; this module does not introduce another scheduler.

The existing combined launcher continues to B without a control-review boundary.
That is an execution-protocol gap, even though the final claim gate rejects a
bad control. Future use must execute A alone through that same existing entry,
review its actual main receipt, and only then authorize B if the control is
qualified. Pinning original bytes or finishing warmup cannot supply that review.
The startup-format details and any intervening review must be retained; they
cannot be silently claimed to reproduce a historical uninterrupted launch.
The existing launcher is not changed and no new runner is introduced here.

=mailbox_layout_entry.qnt= makes this sequence explicit with a trial-state fold,
retains the failed complete outcomes, and checks the source-debt lower bound.
It is wired into =just mailbox-research-gate-check= and the existing aggregate.
External review qualification is still a source/receipt obligation, not a Boolean
that a passing model can manufacture. The original natural stall cause and a
runtime implementation passing 128 remain unresolved.
