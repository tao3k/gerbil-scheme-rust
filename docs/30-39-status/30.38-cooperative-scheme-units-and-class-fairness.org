* Actual API, not another model

ABI v3 adds native control commands 8 (configure) and 9 (observe).
=InstanceDispatcher::configure_scheme_service_budget_on(owner, maximum)= returns
a fixed-owner ticket confirming actual Scheme configuration. Zero disables the
policy and remains the default; 1..=256 bounds consecutive unit grants while
both classes wait. Accepted Scheme jobs or active leases/waiters reject changes.
Older ABI v1/v2 endpoints retain their ordinary execution and reject unsupported
cooperative configuration before native entry.

The Scheme module =:gerbil-scheme-rust/scheme/service-budget= owns the policy:

- =call-with-gerbil-rs-service-unit= surrounds an application-defined unit.
- =call-with-gerbil-rs-service-suspension= releases a held unit during blocking
  work and reacquires through the same class policy on return.
- Persistent Actor children receive the request's Scheme context through the
  existing turn envelope. An enclosing unit releases across the coordinator join.
- The real order handler defines one complete order as a unit. Its existing real
  one-ms wait releases the unit; input, arithmetic, ranks and output stay native.

Rust configures and observes through native numeric values. It dispatches across
instances; Scheme chooses leases, Actors, green threads, waits and continuations.
No Scheme evaluator or application algorithm is translated into Rust or JSON.

* Scheme selection and lifecycle protocol

One service-owned lease represents participating execution on the single-CPU VM.
Two FIFO waiter queues represent short and general units. When both classes wait,
a bounded streak switches classes; when one class is runnable it can proceed.
The selector and counters remain under the existing Scheme mutex discipline.
No host clock, Tokio timer or Rust thread chooses the next green thread.

The final uncontended path directly grants under the same mutex when no owner or
waiter exists. It avoids allocating/reversing a queue node and broadcasting an
empty condition variable on every unit. Contended selection uses the same
record/grant function; it does not skip class debt or FIFO waiters. Streak state
saturates at the configured limit. Dynamic-wind guards remain on all unit paths.

Exceptions and continuation exits release the lease. Reentry reacquires it;
reentrant extents on the same Scheme thread preserve depth rather than deadlock
against themselves. Suspension releases the full reentrant depth and restores it
on return. Retained continuations remain usable after policy disable/re-enable.
Close drains accepted jobs and joins workers, then verifies no unit lease or
waiter remains before closing wake ports and allowing native cleanup.

These are cooperative boundaries. An arbitrary unwrapped handler remains valid
Scheme and is not preempted. A unit may do arbitrarily much work or omit a proper
suspension boundary. GC still pauses the VM; OS descheduling still pauses its
owner. No item count becomes a wall-clock guarantee, and no live Actor migrates.

* Model correspondence and its limits

The unchanged =owner_lifecycle.qnt= is reused. Its =sharedInit= budget-one/class-debt
transition now has a participating native implementation. Native scopes map to
abstract units; child Actors share the original request context, rather than
creating new root/credit authorities. Its current-policy and GC/OS/entry-gap
counterexamples remain applicable outside the cooperative region.

This is not a mechanically proved refinement of every production thread. The
finite model does not prove arbitrary handler termination, GC correctness,
elapsed-time SLOs or all configurations up to 256. The directed qualification
uses budget one. Host entry and fixed session routing retain their separate APIs.

* Independent native controls

- The actual service API rejects invalid bounds and configuration while accepted
  work remains. Explicit feed, request slots and work credits retain their
  existing independent accounting.
- A latched bulk unit plus queued short/general workers must execute =0,1,2,3=.
  The actual selector chooses the order; both class bypass maxima are one.
- The repeated contention control runs 256 real native orders per policy on the
  same VM, with the same explicit in-unit Scheme yield in both arms. It verifies
  every result and requires at least 32 contended candidate grants. This forced
  contention is a functional stress control, not the natural throughput workload.
- The real single-worker service verifies =90,1,2,91,4=, =raise #f=, five submits/
  retirements, wait-release/reacquisition and empty final unit queues/lease.
- The four-VM fixture uses budget one during native types, forced GC,
  continuation execution, exception/projection-panic recovery, class routing,
  abandonment, host wake, backpressure and close. A captured continuation resumes
  with the policy disabled, then resumes again after re-enable on the same Actor.
- Final close requires four joins, zero external roots, removed copied files and
  descriptor return. This does not newly qualify long-term RSS or loader-wide
  reclamation. Five-second actual-progress gates and native O2 are unchanged.

* Directed throughput, p99 and fairness

=just bridge-scheme-service-benchmark --budget-ab= compares disabled policy with
budget one. Both arms use identical live VM identities, the same native O2 image,
four VMs, two Tokio workers, native feed one, slots/work 4/32, batch eight, Scheme
quantum one, explicit short class/router/layout and FIFO client collection.
Each full capture has ten AB/BA samples per arm/load: 8,192 48-line orders and
64 four-line probes on the existing nominal 500-us serial schedule. Correct
outputs, returned credits, native grants and quiescence are asserted.

Grant counts are not completed-order counts: a real wait releases and reacquires.
CPU candidate samples require exactly 8,192 bulk and 64 short grants; mixed samples
require 9,363 bulk and 64 short grants, with 1,171 suspensions. Disabled counters
must stay zero. The native class bypass maxima must not exceed one; final queued
counts and active leases must be zero. These are registered-unit class counters,
not a per-request wall-clock bound or an open-loop offered-load certification.

unit. Two complete captures each validated 40 samples and clean four-owner
teardown. No compiler or model check of ours ran concurrently with these captures;
other tasks were not paused and this is shared-host evidence, not quiet-host

Natural two-class contention was sparse: candidate CPU/mixed contended grants
