#+title: Native owner service cycle and independent result retirement
#+options: toc:nil num:nil

* Decision and scope

[[file:30.62-completion-opportunity-custody.org][30.62]] rejects identity coalescence as a sufficient performance improvement.
The remaining structural boundary is per-result Scheme command construction,
rooted take and projection, followed by a separate owner admission/supply turn.
This change implements that boundary in the actual library, with one native
batch transfer and an input opportunity after each individual retirement.

The explicit experimental policy is =SchemeServiceCompletion::NativeCycle=.
Snapshot remains the default. Rust distributes work across fixed owners; each
owner retains a complete Gerbil/Gambit runtime. Scheme selects Actor/green-thread
execution, owns continuations, exceptions and GC, and keeps affine state local.
This does not translate Scheme to Rust, replace its scheduler, or introduce SMP.

#+begin_src rust
dispatcher
    .configure_scheme_service_completion_on(owner, SchemeServiceCompletion::NativeCycle)?
    .wait(timeout)?;
// Existing SchemeServiceRequest construction, projection and submission stay intact.
#+end_src

* One ownership protocol across transfer, projection and supply

| State | Native graph authority | Credit authority | Next operation |
|-------+------------------------+------------------+----------------|
| Accepted/executing | Existing Scheme job and worker | Existing native/stream permit | Scheme execution |
| Ready/harvested | Owner epoch and claimed IDs | Same permits remain held | One native batch transfer |
| Transferred | Owner-local batch slots | Same permits remain held | Move one slot into a strong NativeRoot |
| Projecting | That result's NativeRoot; other slots remain rooted | This result's permits remain held | Existing typed application projection |
| Retired | Result root dropped; its slot is empty | Return that result's permits | One bounded admission/supply opportunity |
| Snapshot consumed | Empty batch metadata and linear ready token | No deferred completed-result credits | Piggyback epoch acknowledgement |

ABI v9 adds completion mode 3 and command 16. It acknowledges any old consumed
token, harvests readiness using the existing epoch/carry protocol, and takes the
harvested results in one Scheme call. The returned native packet contains the
identity/progress receipt, per-result success/error statuses and native result
slots. This is a typed Scheme object packet, not JSON or serialized application
data. Exceptions are caught per result and use the same bounded formatter as
rooted calls. A failed result does not discard successful peers.

The batch is =[remaining, slots]=, with each slot =[occupied?, payload]=.
Occupancy is independent of payload, preserving false and void as real values.
The optional compiled slot-move ABI checks the owner/root/index and occupancy,
creates a strong root first, then clears the slot and decrements the count.
The native job record's value/failure fields are detached on take, preventing a
yielded worker's old bookkeeping record from retaining a consumed payload.

Rust holds the batch through a non-Send, non-Clone owner guard in the existing
retained arena. Each typed job moves exactly one slot and runs the unchanged
SchemeServiceRequest::project API. Its NativeRoot is dropped and root balance is
checked before its native capacity permit returns. One ready result cannot hold
an earlier result's graph through the batch container after that slot is cleared.
Explicit application retention/shared references retain their existing semantics.

After every retirement, the owner admits at most one eligible queued request,
short-pool input, existing producer step or revocable pool offer. It reuses the
current producer and capacity protocols. There is no recursive collect while the
ready token is owned, no timer, larger window or tuned yield threshold. New work
can enter Scheme before a later arbitrary projector runs; Scheme chooses its
execution. Arbitrary synchronous application projection/foreign code remains
non-preemptible on its owner.

Native service controls have an explicit Work::Control type, distinct from
ordinary native application work. A FIFO head is retained when collect temporarily
removes it. Controls defer until the whole snapshot has retired and its token is
acknowledged; later inbox input cannot overtake that head. Ordinary typed input,
producer supply and safe native application work can still use retirement
opportunities. This prevents an idle setter racing a still-owned empty token.
A real setter queued from the last projector must complete successfully after
the barrier, rather than fail an incidental non-idle check. The existing model
also checks the control barrier before/after final projection and acknowledgement.

Acknowledgement cannot consume a live batch. Native idle configuration and
admission count transferred slots as well as job-table entries. The previous
fresh carry-epoch and stale/duplicate acknowledgement guards remain intact.

* Root quota, errors, cancellation and close

One internal batch root is tagged in the existing arena, separately from the
public 65536 application-root quota. There is at most one such root per owner.
Rollback, explicit release and teardown clear the tag together with the canonical
arena entry. No parallel root registry is introduced. The batch does not silently
reduce the application's usable retained-root capacity.

Application reply bounds do not truncate/replace Scheme exception diagnostics:
the existing 4096-character/16384-byte diagnostic bound is independent of an
application's output quota. Older native images reject NativeCycle before changing
policy if ABI v9 or the slot-move symbol is unavailable. Production and qualification
image export lists include that actual symbol. The qualification image exposes
the existing full object ABI so void is validated through native type inspection.
The intra-package runtime dependency uses Gerbil's relative module import.

Unentered cancellation returns only unentered Rust admission. Entered observer
timeout/cancellation does not discard Scheme execution, its result graph or the
native permit. Delivery abandonment preserves normal per-result cleanup and
rolls back only roots created by that application projector, not the older batch.

A native slot-transfer failure is distinct from a failed application projector.
The former cannot return native or stream credit while native ownership is
unresolved. Those credits move to the owner's drain custody; close joins/clears
native work before the credits drop. Ordinary Scheme exceptions and Rust projection
panics after a successful slot move still retire individually and preserve peers.

Closing owners claim no new pool supply from an inter-projection opportunity.
Accepted work drains; native close clears any remaining batch slots before joins,
the service-owned reference protects the graph if Rust's batch arena guard has
already unwound. Drain credits drop after native close. Failed native quiescence retains the existing quarantine rules. No graph, continuation or root
becomes transferable to another OS owner.

* Existing model and actual native controls

The existing service_sharing lifecycle refinement adds NativeCycle and logical
owner-held batch slots. Transfer preserves existing roots and capacity; individual
project clears one logical slot and uses the original complete/credit transition.
A positive witness admits a short request between two bulk retirements while a
peer root remains protected, then drains timeout/close. A required mutation returns
credit before clearing its slot and must violate the original root/capacity safety.
This extends the existing model rather than creating another scheduler model.

The initial focused gate passes in 86.96 seconds (85.26 seconds in the test).
The final expanded gate including the control barrier passes in 226.46 seconds
(225.95 seconds in the test), alongside other build activity; these durations
are verification receipts, not performance comparisons.
Original completion, coalesced/carry and native-cycle scenarios remain included;
sampling uses 1000 x 64 traces for each of the original, coalesced and native-cycle
initializations in their two existing finite instantiations. Required bounded-class,
stale-ack and early-credit mutations produce counterexamples. Two bounded epochs
and finite samples do not establish unbounded liveness, wall-clock fairness, OS
scheduling attribution or performance.

Actual native controls cover:

- Three real latched Actor batches made ready together and transferred as one batch.
- Strong root count 2 during each projector (batch plus current result), count 1
  between projectors, and native pending-slot counts decreasing independently.
- A queued real owner request runs after the first retirement and before later
  projectors, observing that the prior native root and slot/work credits returned.
- GC while two results remain protected; full 65536 application retained roots
  coexist with the internal batch root (65537), reject the next application root,
  release back to the single batch root, and preserve remaining result contents.
- False/void payloads through the actual native type API; Scheme diagnostics under
  an eight-byte application reply quota.
- Real service closure invalidates an outstanding snapshot: failed slot transfer
  skips later projectors and follows clean owner drain with no roots/credit leak.
- Existing four-VM conversion, GC, multishot continuation, Scheme exception, Rust
  construction/projection panic, cancellation, timeout and close tests use the
  new policy on actual owners. Default and previous completion controls remain.

These are separate from the historical unattributed exit-70 watchdog. Its exact
failed native image/last progress was not retained, so current model/native passes
cannot explain it. The dedicated failure control still proves the unchanged
five-second deadline, raw failure evidence and phase messages that do not renew
progress. No new timeout is widened.

* Next structural boundary from this evidence

Mixed admission p99 improves from 289.750 to 150.083 us while short pending p99
rises from 449.000 to 564.167 us and end-to-end native short p99 rises from
474.375 to 584.792 us. Earlier admission is not sufficient for earlier completion.
Do not subtract pooled quantiles to manufacture an execution or OS-wait duration.

The captured stage intervals provide a further bounded comparison:

| Load | Stage | Snapshot p50/p99 (us) | NativeCycle p50/p99 (us) |
|------+-------+-----------------------+-------------------------|
| cpu | Bulk construction | 2.333/404.917 | 2.375/420.459 |
| cpu | Bulk application projection/retirement | 5.417/20.458 | 5.750/23.667 |
| mixed | Bulk construction | 2.500/444.750 | 2.500/448.250 |
| mixed | Bulk application projection/retirement | 5.708/24.542 | 6.042/22.667 |

There is no broad projection-stage improvement: bulk medians rise in both loads,
while only mixed bulk projection p99 falls. Construction has sub-3-us medians
and roughly 400-450-us p99 intervals in both arms. Those wall intervals can include
allocation, GC and scheduling; they do not identify which caused a particular
spike. The capture contains no same-spike OS attribution evidence.

The code now makes the remaining ordering conflict explicit: immediately after
one result retires, native construction/entry of fresh input can occur before
other already-ready results project. Correct root/credit return and fewer Scheme
take commands do not by themselves prevent this contention.

The next protocol should separate preparing owned Rust input from entering native
construction, and define precedence for ready-result retirement versus new bulk
construction. Reuse existing producers, revocable offers and capacity reservations;
staged input must stay bounded, cancellable before entry and free of Scheme roots.
Native batch construction/projection capabilities should preserve the generic
Scheme request path and full native types. This is the next design/implementation
boundary, not a claimed root cause or an implemented speedup. No additional matrix,
unchanged capture or yield-threshold tuning is admitted by this report.
