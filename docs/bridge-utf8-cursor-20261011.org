* Source, baseline, and algorithm

Entering production is =4d0fc584c8f2eb87b19333edfa52ab3c14693c5a=;
the current checked-inline control remains frozen at =345b172=.
Historical baseline =6ad680c6311957eadf2529765ab1efd751132554= is retained.
The only production algorithm change replaces repeated output-base indexing
with a local advancing output cursor. Matching official Gambit source uses
this convention in =lib/c_intf.c:398-443= (=___UTF_8_put=) and
=lib/c_intf.c:3250-3290= (Scheme-to-UTF-8 conversion).
The source was read locally under the Gerbil SDK source checkout; no download
or kernel change was needed.

The adaptation does not adopt the SDK's historical five/six-byte encodings,
NUL-terminated conversion, extra size pass, or reference-counted allocation.
Unicode scalar rules, all type/capacity/range checks, pointer tag conversion,
256-character polling bound, and exception containment remain unchanged.
Empty spans return before any arithmetic on a potentially null destination.
Pointers remain local to a synchronous allocation-free leaf; no Scheme body
pointer survives polling. Rust output and Scheme source are distinct objects.

Both leaf functions in the same ARM64 benchmark binary
show different addressing: the cursor enables post-indexed/fixed-offset stores;
the frozen control retains output-base plus running-index stores. This confirms
the tested source change reaches machine code under unchanged =-O2= flags.
It is consistent with the reduced CPU cost, not a claim of an identical gain
on other CPUs or corpora.

* Same-process changing-text admission

Every timed request reads one of four alternating current rooted texts, with
complete content comparison and full UTF-8 validation. Separate preflight
also mutates a live string across encoding boundaries and rejects every
surrogate. No encoded snapshots are used for these comparisons.
ABBA retains twenty samples per variant at 1,000, 10,000, and 100,000 requests.

* Allocation, GC, and non-CPU time

At 100,000, the matched public run has 1,237 collections for each variant.
CPU medians are 602.638 versus 462.360 ms; GC CPU medians are 11.627 versus
11.325 ms. The large improvement is in CPU computation, not a GC policy change.
The same allocation and complete validation remain in both sides.

Complete seven-phase diagnostic
contains 420 rows: seven phases, three loads, twenty samples per phase/load.
At 100,000, owned wall/CPU medians are 466.091/464.157 ms; encoding CPU
377.332 ms, validation 96.110 ms, allocation request/release 2.711 ms,
empty public entry 15.639 ms, and empty leaf dispatch 32.414 ms.
These independent diagnostic phases are not additive. CPU already includes
GC. Their inter-run comparison against the previous cost receipt is diagnostic,
not a replacement for the contemporaneous ABBA admission above.

Rust reserves 13,660 bytes for 8,196 encoded bytes, unchanged. The 5,464-byte
spare capacity is not RSS and only one output is live in this fixture. This
change neither increases that reserve nor adds shrink/counting overhead.
GC and allocation remain targets for subsequent separately qualified changes;
they are not claimed to be solved by changing the output cursor.

* Evidence boundary

These are single-owner bridge transfers, not Org parsing, independent-VM
parallelism, or SMP acceptance. SMP remains explicitly skipped, not passed.
The existing supported FFI, AOT, Rust concurrency and Bazel CI gates are not
relaxed. Any committed new head needs its own remote CI result.
