* Source research and rejected changes

The matching local official Gambit =lib/c_intf.c:1270-1300= uses a bounded
input cursor in its stream encoder. The input-cursor candidate adapts this
local iteration convention, preserving the output cursor and every guard.

The no-alias candidate follows
[[https://gcc.gnu.org/onlinedocs/gcc/Restricted-Pointers.html][GCC's restricted-pointer documentation]]
for the already-disjoint typed Scheme input and Rust output. The installed
SDK's compiler recipe uses =-fno-strict-aliasing=; this explicit local contract
was tested without changing that flag or the SDK.

The packed candidate follows
[[https://gcc.gnu.org/onlinedocs/gcc/Library-Builtins.html][GCC's C-library builtin documentation]],
expressing exact two/three/four-byte output through fixed-size byte arrays and
=__builtin_memcpy=. This avoids alignment casts, endian assumptions and
overwriting a fourth byte for a three-byte scalar. The documentation does not
promise every builtin expression will be faster.

Packed and frozen leaf machine code in the same binary
shows halfword/word stores with additional packing operations. There is no

ms; both have 1,237 collections. This is not a GC or heap-allocation regression.

At 100,000 the encoding diagnostic CPU is 376.814 ms, full validation
96.452 ms, allocation request/release 2.686 ms, empty public entry 15.662 ms,
and empty leaf dispatch 32.310 ms. Independent phases are not additive;
total CPU already includes GC. GC is approximately 2.3% of owned CPU here,
so eliminating GC alone cannot promise another large speedup.

The pinned =simdutf8 0.1.5= source selects NEON when either its feature or
=target_feature="neon"= is present. The current Rust target reports NEON;
an extra Cargo feature is not a missing optimization switch. Full validation
must stay, not be replaced by a provenance assumption or cached text.

Rust still reserves 13,660 bytes for 8,196 output bytes: 5,464 spare bytes,
40% of capacity, one live output in this fixture. Cumulative reservation
traffic at 100,000 is 1,366,000,000 bytes, not resident or simultaneously
live memory. No candidate increases reserve or introduces another heap
allocation. Counting to exact size or shrinking adds work; neither is admitted
without matched wall-time benefit. Reuse or retained-many-results workloads
would require their own explicit memory/lifetime and throughput qualification.

No production optimization is admitted this round. The retained test control
and negative evidence prevent false attribution and repeat regressions.
These results are bridge transfers, not Org parsing or Scheme parallelism.
SMP remains explicitly skipped; no kernel/SDK change or acceptance relaxation
is made. Remote CI must be checked separately on the exact pushed head.
