* Completion fairness beyond equal final counts

Final completion counts and =jain_worker_completion_coverage= describe finite coverage. They
can be equal even if one group is serviced only after another group's entire
queue drains. The harness now also records:

- Per-assigned-owner maximum time between completions while offered work
  remains, including initial waiting after native window admission.
- Per-assigned-owner maximum intervening completions by other owners while
  its offered work remains.
- Per-Scheme-Actor-worker intervening completions, using the native Scheme
  completion ranks, in addition to rank displacement and completion counts.

Owner attribution follows the current native API's round-robin contract.
The Rust implementation resets its admission clock for each 128-request
window; metrics therefore never sort native-ready timestamps across windows.
Global input-index owner assignment continues across windows. Equal native
timestamps use input index as a deterministic tie breaker. Once a group's
last offered job finishes, later work by other groups is not charged as that
group's starvation. These are finite completion diagnostics, not a proof of
starvation freedom. Actor ranks do not provide per-item elapsed time.
