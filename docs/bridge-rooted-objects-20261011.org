#+TITLE: Rooted object and binary integer qualification
#+DATE: 2026-10-11

* Ownership boundary

Scheme word zero is the fixnum zero, not a null root token. Trusted object
exports accept it; untrusted raw-handle constructors continue to reject zero.
Strong registry tokens remain positive. A unique missing-value sentinel
distinguishes a stored false value from an absent token.

=RootedSchemeObject= owns one registry token. =SchemeObjectRef= borrows that
owner; =RootedObjectBatch= owns one strongly rooted Scheme vector containing
the complete shallow element snapshot. Collection copy requires the runtime
lifetime in its output type. Neither roots nor
borrowed references can be transferred to another runtime thread. Successful
copy roots the complete snapshot before replacing output. Rejected capacities
publish nothing; the separate raw token-span release API rejects duplicate
tokens before any release.
Input roots may be released after collection construction. Element roots
remain valid after releasing the collection and forcing normal SDK GC.

Vector, proper-list and pair projections are covered, including nested
objects, false, zero and empty vectors. This is not a claim that maps,
homogeneous numeric vectors or rationals have dedicated serializers.

Arbitrary-precision integers use canonical little-endian magnitude plus sign,
not decimal text or machine truncation. Empty magnitude is nonnegative zero.
The large-value algorithm transfers eight-byte limbs inside the Scheme
foreign boundary. Rust invokes one create/copy operation per complete value,
not a foreign call for each byte. Reusable output stages data before swapping
the published integer. Incorrect types leave the previous output unchanged.

* Build defect and regression

The included foreign bodies execute Gambit syntax, not Gerbil syntax. The
Gerbil-only =1+= identifier caused an exception on collection construction.
Additionally, Cargo and Gerbil incremental build inputs initially omitted
the included source, so a changed input fingerprint could accompany stale
generated code. The fix declares Cargo invalidation and official =std/make=
=gxc:= =extra-inputs:= for the include. Generated SCM is regenerated by
=just bridge-regenerate=, not manually patched.

The installed =src/std/make.ss:162-173= defines the extra input contract;
=251-260= checks input timestamps against outputs. No SDK or kernel changed.
The UTF-8 source baseline is unchanged. Compiler timestamps and hygienic
generated identifiers can differ after regeneration; generated byte identity
is not claimed.

* Matched measurement

=just bridge-objects-matched= uses one in-process Scheme owner, six families,
1,000 / 10,000 / 100,000 requests and ten ABBA groups: twenty full batches
per variant and load, 720 batches total. Individual request percentiles use
nearest rank. Per-request P95/P99 are nanoseconds; batch/GC/CPU wall times
are milliseconds; throughput is requests/second; memory is bytes.

The control retains individual element ownership and release, without
temporary vector allocation for each list or pair element. Integer control
is the byte-wise Scheme algorithm with the same native entry/exit boundary,
input, sign, validation and root release. This measures bridge projection and
round-trip ownership, NOT Org parsing or Scheme parser parallelism.

Observer storage is separated from payload and staging capacity. RSS is a
process high-water mark, not per-variant live memory or allocated-byte count.
Scheme heap size is capacity, not live payload. CPU and context-switch
accounting are process scoped. GC counters describe the same owner VM.

The initial complete receipt, =benchmarks/20261011-objects-abba.log=, rejected
pair and one-byte integer candidates at every load. All other twelve gates
passed and final registry accounting found zero leaked roots. Negative
receipts remain intact. Pair temporary vectors and one-byte loop bookkeeping
were then removed; the follow-up must satisfy the SAME wall/P95/P99 gate,
not an amended threshold.

The second complete receipt, =benchmarks/20261011-objects-adaptive-abba.log=,
passes all three one-byte integer gates, but still rejects all three pair
gates. Pair GC counts exceed the scalar control. The pair handler captures
two mutated bindings, while batch release redundantly validates each token
again after the complete validation pass. The next candidate stores rollback
tokens in one fixed vector and performs only table deletion in the validated
mutation pass. This preserves all-before-any release, rather than deleting
validation or weakening failure atomicity. The rejected generated-runtime
diff is retained beside that receipt for reconstruction.

The third complete receipt, =benchmarks/20261011-objects-release-abba.log=,
still fails the pair gates and two short-load tail gates; it is not admitted.
Its generated-runtime diff is retained. An immutable-first-root candidate was
rejected and reverted: allocating the rollback closures after registering
the first root creates a failure window that can leak that root. Its timing
run was stopped, not counted as a completed matrix or accepted optimization.
The retained implementation installs rollback protection before registering
either root. Throughput cannot justify losing this ownership invariant.

* Whole-snapshot algorithm

Per-element rooting was the structural cost: an eight-element batch still
registered and released eight table entries and retained two Rust token
buffers. The replacement takes one native shallow vector snapshot and one
strong root. Official Gambit =##vector-copy= copies vector element references;
list and pair views already produce a fresh vector, so they are not copied
again. Nested objects retain the same object identity, exactly as individual
element roots did; this is not a deep AST reconstruction.

Rust owns a constant-size snapshot descriptor instead of token arrays. Its
borrowed element references contain the snapshot root and an index, never a
borrowed GC-managed word. Scalar and integer projection resolve that index
inside the Scheme foreign boundary. The snapshot therefore survives original
collection/input-root release and GC. Replacing or clearing a batch releases
one root. Regression tests assert precisely one additional registry entry
for the entire batch across fifty replacements, and exercise nested bignum
projection after releasing original owners and forcing GC.

The superseded per-element-root collection-copy ABI and pair optimization
helper have been removed, not kept as a parallel production implementation.
Its negative timing receipts remain. Scheme snapshot storage still scales
with element count; constant Rust descriptor size does NOT mean zero memory
or a zero-copy payload. Current Rust memory accounting includes baseline Vec
metadata as well as capacity, and the complete snapshot descriptor.

The full workspace receipt records 655 passed tests and eight existing
ignored tests across 37 target summaries. This includes the two compile-fail
ownership checks and scalar-FFI negative AST controls for collections and
integers. Local Bazel execution is unavailable: its executable is not on the
host PATH. The Bazel =scheme/**/*= input glob includes the added source, but
that static inspection is not a Bazel test pass.

* Admitted local receipt

=benchmarks/20261011-objects-cohort-small-abba.log= completes all 720 batches
and 26,640,000 measured requests, excluding warm-up. All eighteen family/load
gates pass (wall, pooled request P95 and P99); final retained-root count is
unchanged. This is the selected whole-snapshot/fixnum/limb implementation,
not any rejected candidate above. Zero/one-byte magnitudes use official
=___FIXNUMP=, =___INT= and =___FIX= inside the foreign boundary; larger
magnitudes retain the limb algorithm. Raw and indexed integer projection
share one implementation, rather than duplicate encoding loops.

The Rust collection snapshot descriptor is 16 bytes at every load, versus
88 control bytes for an eight-element Vec (24-byte descriptor + 64 capacity)
or 40 bytes for a pair (24 + 16). There are no Rust per-element token/staging
buffers. Scheme still allocates the snapshot vector; it is accounted through
GC and heap metrics, not called free. Integer benchmark memory counts the
raw output capacity (1/32/256 bytes), not the safe =BigIntegerBuffer='s two
reusable buffers or common input vectors. Timing observation alone reserves
328,000 / 3,280,000 / 32,800,000 bytes. These scopes must not be conflated.

For example, the first 100,000-request Vector ABBA group has control GC
counts 128/129 and selected counts 62/62; GC wall is about 22.9/22.4 ms
versus 4.0/3.8 ms. Pair GC counts can increase while GC time and wall improve;
fewer GC cycles is not the admission criterion. Process RSS high-water
is shared across variants and includes observer buffers. Process CPU
snapshots include capture overhead and are not exact owner off-CPU time.

* Scheduling and remote qualification

The existing owner/Tokio handoff audit remains distinct from these synchronous
type projections. Response handoff includes publication, synchronization,
remote injection and runnable-task waiting; it cannot be labeled exclusively
as mutex time. No rejected receive batching or response-channel experiment
is reinstated. A single Scheme owner is not parallel Scheme parsing.
