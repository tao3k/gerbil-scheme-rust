* Diagnostic boundaries

The preexisting fixed-session API omitted the host clocks already available on stateless =library.call_many=. Optional session observations now cover Python input conversion, token-wrapper construction and the return from detached Rust work. Bulk projection observes Python value validation, native projection wait, Python materialization and release wait.

=gil-return-*= spans begin immediately before detached work returns and end after PyO3 reacquires the interpreter. They include reacquisition, OS scheduling and binding return overhead; they are not a pure GIL mutex timer. Time before Python method entry is not isolated as GIL time. Client entry lateness and current-thread CPU are recorded separately.

Native owner spans distinguish preparation-to-owner-start waiting, native construction and Scheme-call wall time. Optional cumulative SDK snapshots split GC user/system/real seconds, owner-thread CPU, external roots and collection counts between construction and execution. GC is included in the measured phases, not additional time to add to them. Projection spans retain their own queue/execution/GC observations. Host envelopes overlap owner spans; sums of quantiles do not reconstruct end-to-end latency. Diagnostics are opt-in and bounded, and measurement failures/dropped spans invalidate a diagnostic cohort.
