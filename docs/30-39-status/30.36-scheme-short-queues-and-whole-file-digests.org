* Actual API and ownership

=SchemeServiceRequest::short_service()= defaults to false. True requires exactly
one declared work unit and no Scheme Actor lane. Validation snapshots this class
before admission/construction. The private native submit header adds an explicit
short flag, independently of application data layout and owner routing.
=SchemeServiceRouter= forwards the request declaration. A shared router still
protects one short / three bulk callbacks only for its cooperating callers.

The endpoint negotiates ABI v2. ABI v1 still accepts general requests; a short
request against v1 is rejected before native construction. No fallback changes
execution semantics. Arbitrary Scheme programs, exceptions including =raise #f=,
GC, closures, green threads and multishot continuations retain their existing
execution and fixed-thread ownership. Rust handles cross-instance dispatch,
admission, native type construction and owned result projection.

* Scheme work, wake and retirement protocol

- Short and general requests have separate pending queues. A worker alternates
  eligible classes when both are queued; lane eligibility is preserved.
- A short request is one declared work unit. The worker yields between transitions
  involving short work. An already executing handler is not interrupted. This is
  a cooperative work-count boundary, not a duration bound on arbitrary code.
- Short and general completions have separate amortized constant-time FIFOs.
  With short work outstanding, one owner turn returns at most one ID from each
  class, giving host admission another turn between projections.
- The existing Scheme condition-variable predicate includes both ready queues.
  Partial collection cannot make the owner sleep while completions remain.
- Strong job graphs, errors and native capacity remain held until take/projection.
  Receiver abandonment does not release accepted work. Close drains all classes,
  joins persistent workers/watcher and closes the existing native wake ports.

The general-only path still drains ready results together and has no newly chosen
runtime default. No SMP path, Bash runner or Scheme-to-Rust compiler is added.

* Generated-file digest correction

The v1 header updated only a comment when build input identity changed. It is
removed. Each =scheme/generated/*.scm= now consists of raw compiler output; its
external =.scm.sha256= receipt records an entire-file SHA-256 and framed build-input
identity. A change even to a compiler comment is covered by the digest.

The canonical native build remains responsible for regeneration. Timestamp-bearing
Gerbil output is not falsely advertised as deterministic byte-for-byte output
across separate compilations. Receipt validation is separate from native build,
semantic tests and exact-head CI. No SDK compiler patch or timestamp stripping is
introduced. The initial migration removes only the old metadata line and preserves
every byte of the previously generated body.

* Directed measurement and boundaries

=just bridge-scheme-service-benchmark --short-service-ab= compares general service
against explicit short service with identical class routing, four VMs, two Tokio
workers, slot/work limits 4/32, batch eight, native short layout and FIFO client
collection. CPU and mixed native workloads remain unchanged. This adds one pair,
not a larger scheduler/thread matrix. Startup is outside sample windows; five-second
progress gates remain unchanged. Each row verifies native numeric outputs.

The new per-request post-admission interval separates admission from waiting until
native construction. It is still combined owner queue/wake/OS cost; construction,
pending native work and projection/retirement remain separately recorded. This Rust
bench does not include Python/GIL costs. Aggregate quantiles must not be subtracted
for causal attribution. Existing negative short-layout and class-routing results
are retained. Performance admission is not established by the directed captures below.

* Verification

The native single-worker fixture uses the real dispatcher and the same service
protocol. A latched first request holds both queues; earlier general requests and
later short requests must execute =90,1,2,91,4=, preserving each FIFO and alternating
classes. =91= raises =#f=. Invalid work/lane declarations must fail before entry,
completion turns must respect their budget, and teardown must return roots/files.
The existing four-VM continuation/GC/error/backpressure/close and descriptor-return
checks remain active.

The existing =owner_lifecycle.qnt= is reused with a partial-retirement scenario:
a ready graph left behind retains its root and prevents parking; close drains it.
Both small and wide domains passed all 28 scenarios. This does not model FIFO,
preemption, fairness bounds or OS latency; native checks and measurements own those
claims. The generated-file unit suite passed 18 tests including comment/body/input
drift and missing-receipt controls.

Two native fixture runs failed missing-export preflight. The second established
the omitted image export-list entry, which is repaired in the build contract. Both
failures remain recorded. An initial stale-build explanation was insufficient.
Strict benchmark lint failures were repaired with an explicit short execution-mode
enum and bounded argument list, without lint suppression.

* Concrete ingress-order correction

The owner pump previously advanced Scheme through =ready/yield= before inspecting
an already-populated host inbox. A short payload therefore could remain in Rust
while Scheme ran a turn without being able to select that job. The corrected
pump checks the next FIFO inbox entry first. An explicitly classified short entry
is constructed/submitted before the next Scheme advance; general entries retain
the previous collect-before-entry behavior. No FIFO entry is bypassed, no Scheme
thread is scheduled by Rust, and native capacity/root retirement is unchanged.
This removes an identifiable extra progress boundary; it does not prove that all
preconstruction delay came from that boundary.
