#+title: Scheme completion handoff and owner service opportunities
#+options: toc:nil num:nil

Follow-up: [[file:30.62-completion-opportunity-custody.org][30.62]] separates completion opportunity, ready-token custody and per-result retirement.
The two rejected captures and historical watchdog boundary below remain retained.

* Evidence and protocol decision

[[file:30.60-dedicated-offer-ports.org][30.60]] retains CPU native short p99 +18.20%, short pending p99 +17.81%,
and mixed bulk p99 +5.53%. Admission, construction and projection p99 do not
establish that these are pure GC or OS costs. Existing data does not justify
another unchanged capture or a wider dispatcher matrix.

The source reveals two coupled decisions. A worker publishes completion and
selects its next job under the same Scheme lock before yielding to the owner.
New short work admitted during that yield therefore cannot participate in that
selection. Separately, ready harvesting always yields before reading results;
when no short job remains, it hands the entire bulk completion backlog to Rust.
Thus execution, result retirement and new admission share an uncontrolled host
opportunity boundary even though Rust input queues are separated.

The explicit experimental =SchemeServiceCompletion::FairHandoff= protocol:

1. Scheme publishes the completed graph and notification under its mutex. If
   an eligible successor exists, it releases the mutex, yields to its scheduler,
   then selects using its existing class/FIFO/Actor-lane rules. It does not bind
   the successor before handoff. If no eligible job exists, it publishes the
   worker as idle under the same mutex and uses the blocking receive as the
   natural handoff. New affine jobs remain on their original Scheme worker.
2. An already-ready result is harvested without an unconditional compute yield.
   If no result is ready, the existing Scheme green-thread yield still applies.
3. Each harvest returns at most one short and one bulk identity, including when
   there are no short jobs. Further results remain rooted and visible in Scheme;
   the native wait protocol cannot sleep past them.
4. Rust projects the returned identities individually and releases each result's
   native permit immediately after its projection/root balance. The next owner
   turn can admit short input or supply more work. No resource return is deferred
   across a later application projector.

The library API is =configure_scheme_service_completion_on(owner, policy)=.
Its ticket confirms native readback of the requested mode through private service
ABI v7, command 13. Native configuration requires an idle job table and no active
cooperative lease; activity rejects the switch. =Snapshot= remains the default.
The budget and wake settings query retains its existing shape. Older native
endpoints reject the new operation through the Rust version check.

Scheme retains full types, Actors, green threads, continuations, GC, exceptions
and native compilation. Rust distributes across complete fixed-owner runtimes;
it neither schedules Scheme continuations nor migrates entered graphs. A yield
is a scheduling opportunity, not an OS latency guarantee or preemption of an
arbitrary synchronous constructor/projector/foreign call.

* Historical watchdog: recovered facts and missing evidence

The initial dedicated-port native run exits 70 at the five-second progress gate.
Its raw log contains the test header and abnormal exit, but no last completed
event, active phase, native stack or exact failed test-image snapshot. Libtest
capture loses buffered progress on =process::exit=. A later same-binary diagnostic
run passes; that does not identify the original stalled operation or its cause.
The original failure remains UNATTRIBUTED and cleanup for that run UNVERIFIED.
Neither subsequent native passes nor the model close that historical obligation.

The diagnostic protocol now separates completed progress from phase context.
A =PHASE= event changes the failure label but never renews the absolute progress
deadline. Failure writes last completed event, phase and cleanup status directly
to raw stderr before exit 70. Passing phase events add no diagnostic output.
A bounded child-process control uses ordinary libtest capture and deliberately
sends phase context continuously without completing work. It must still exit 70
at the unchanged five-second gate and preserve its checkpoint/phase on stderr.
Its parent kills a defective child after ten seconds; this is a controller bound,
not a widened native acceptance deadline. No keepalive can admit stalled work.

* Reused model and native acceptance

The existing =service_sharing= module in =specs/owner_lifecycle.qnt= now distinguishes
native ready roots from IDs handed to a host projection turn. Harvesting does not
release roots or capacity. The harvest is bounded independently by owner and
class; close and observer abandonment retain unprojected roots and wake duty.
Projection uses the original lifecycle completion/credit transition. Existing
worker assignment remains separate from completion, matching successor selection
after the handoff. This is a finite opportunity/ownership model, not a theorem
about OS scheduling or unbounded application execution.

Two-domain scenarios cover partial harvest, retained ready roots, close and
abandonment, and reject an unbounded same-class snapshot. The targeted gate runs
1000 sampled traces of 64 steps per domain and requires mutation counterexamples.
The first random mutation search failed to find a violation; its negative receipt
is retained. The mutation gate now starts from the explicitly reachable state
with two same-owner short results ready. It retains the same invariant and proves
the mutation is rejected rather than treating an unexercised control as passed.
The targeted gate passes in 49.54 seconds; the model is not rerun unchanged for
additional numbers. Existing aggregate wiring includes these checks.

Native controls exercise both completion policies with one persistent Scheme
worker, short/general FIFO, exception retirement and active reconfiguration
rejection. A bulk-only fixture checks the one-result boundary without a short
job. A projection callback admits a new typed short request after the first bulk
completion while two bulk jobs wait; it must participate before successor bulk
selection. The four-owner contract retains GC, multishot continuations, errors,
backpressure, cancellation/timeout and close drain; owners 1 and 3 explicitly use
FairHandoff. The directed benchmark switches all four owners by arm.

The completion-before-successor revision passes all four native tests in
19.11 seconds, including the
captured child-process watchdog failure control. Warnings-denied Clippy and the
release benchmark build pass against the final benchmark CLI. The earlier native
fixture failure is retained: polling Tokio admission inside a synchronous native
projector lacked a reactor context. The test now explicitly enters the caller's
existing Tokio handle before its nonblocking admission poll. No Scheme VM moves,
new executor or production runtime change is involved. An earlier duplicate

completion. That needs explicit outstanding handoff/ready ownership and a
work-conserving batch boundary; another unchanged capture or yield-threshold sweep
would not answer it. Snapshot, Queued bulk and Broadcast short defaults remain.

** Final eligibility-driven handoff

Source review after the first capture identifies a redundant native yield: a
worker with no eligible successor yields once, resumes to publish idle, then
blocks on receive. The final protocol publishes idle in the completion critical
section and blocks directly. An eligible successor still requires a handoff
before class selection, preserving the actual late-arrival contract. This is an
eligibility rule, not a changed budget, spin interval, timeout or yield threshold.
The existing model already separates ready completion, successor selection and
blocked/idle scheduling; its source and gate are unchanged for this implementation
refinement. Native acceptance and the changed capture are separate gates.

Final native acceptance passes all four tests in 21.26 seconds, including both
completion modes, actual late short admission, natural idle receive, close drain
and the captured watchdog failure control. Warnings-denied Clippy and the final
release benchmark build pass. The existing finite-model source is unchanged.

The changed capture completes 40 samples in 6.70 seconds with exit 0. Both arms
retain ProgressFair supply, Selective short routing and identical live VMs. Every
sample conserves offers and has no pending offer at its boundary; four owners
join, roots are zero, services quiesce and copied image files are removed.

The revised eligibility rule removes a real redundant scheduling opportunity,
but its complete candidate still fails the matched control. It does not justify
asserting that the earlier performance loss was entirely the extra yield.
Absolute control throughput and tails differ across captures; no cross-capture
causal comparison or quiet-host claim is admitted. The first negative remains
above. Defaults stay unchanged, and the explicit policy remains experimental.

Minimum owner progress remains about 98.8% in both loads/arms; minimum Actor
peers remain CPU 1 / 1 and mixed 0 / 0. This is no new fairness or latency bound.
The next architectural obligation is an outstanding completion-opportunity
protocol that retains the demonstrated late-admission selection boundary while
coalescing completed bulk graphs without a mandatory host crossing per graph.
Its ownership, ready-token and class-fairness rules need to precede implementation;
no additional unchanged performance sampling is performed in this round.
