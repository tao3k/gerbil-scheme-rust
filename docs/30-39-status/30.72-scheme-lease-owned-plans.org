* Ownership and algorithm

Scheme owns a per-class permission cache in its existing work policy. It stores
the contended or maximum span allowed for the next lease. It does not store Rust
admission credits, Scheme roots, result IDs or already-selected continuations.

| Event | Cache authority / boundary |
|-------+----------------------------|
| Policy configuration | Idle service and queues; new policy object, both class permissions initialized |
| Short submitted / actually started | Pending obligation and cache updated together under the Scheme budget mutex |
| Opposite-class queue push / pop | Existing budget mutex updates queue and class permissions |
| Short result ready / harvested | Ready/offered generations and cache updated in the same critical section |
| Work handoff | Offer generation and cache updated under budget mutex; release/yield/reacquire occurs outside it |
| Direct uncontended lease grant | Copies a cached permission under the existing mutex; no repeated work-policy queue scan or cache refresh |
| Policy replacement | New identity; old continuation cannot charge it |

Service-control mutations take service lock then budget lock. Lease release
never takes the service lock. No Scheme interrupt disabling or foreign thread
mutation is introduced. Publishing an obligation before invalidating its cache
would leave a preemption gap; the two updates are atomic. Grant copies permission
before unlocking, rather than reading a cache that another green thread may be
part-way through updating.

A cold =make-gerbil-rs-service-work-layout= validates a positive logical cost.
=call-with-gerbil-rs-service-work-layout= uses the copied permission when acquiring
the existing lease. The real order handler uses preconstructed four/48-record
layouts, with a general positive-cost fallback for other native inputs. It still
validates native Scheme types and record shape. This is not an alternate Rust
implementation or a synthetic payload shortcut.

The whole-body path receives no checkpoint closure, performs no per-record
work-policy check, and reports no terminal checkpoint. Normal whole-body cost
and plan diagnostics are folded into the existing release critical section.
The contended path retains explicit bounded Scheme checkpoints and the existing
continuation-safe suspension/class arbitration. Necessary lease acquisition,
release and exception ownership checks remain. No claim of zero handler overhead
is made: mode dispatch, layout access and activation state still exist.

* Bounds, accounting and continuations

Contended permission is four records; maximum permission is 48. A bulk batch of
eight orders is not a 384-record indivisible block. Actor quantum and per-order
lease release remain. A short request arriving after a grant has copied 48 may
wait for that one selected block, even if it arrives before arithmetic begins.
Cache invalidation changes future grants; it never rewrites that active span.
Whole four-record short work can fit a contended permission without checkpoints.
Consequently observations explicitly distinguish =whole_plans= / =sliced_plans=,
not uncontended/contended requests.

The bound covers cooperative declared logical work, not GC, OS delay, type
construction or arbitrary user code. I/O releases the lease using the existing
suspension protocol. A resumed activation retains its selected bound; future
activations use updated cache permissions. No frequent unconditional yielding is
added to the CPU path.

Continuation entry reacquires the Scheme lease; its captured span remains fixed.
Each successful whole-body return charges its retained declaration. On partial
continuation replay this is conservative declared work, not an exact count of
instructions or reexecuted records. An exceptional/escaped unfinished body gets
no whole-body credit; completed explicit sliced checkpoints retain their charges.
The identity fence prevents old activations from charging a disabled/replacement
policy, including replacement with a smaller maximum. Such old code retains its
original declared bound; it does not inherit a new four-record preemption promise.
The independent item ledger prevents duplicate item completion. None of these
work counters release roots, result custody or Rust capacity early.

The handler boundary returns one Scheme object, matching the existing service
API. Computation inside retains Scheme values, exceptions, actors, green threads,
GC and multishot continuations. Rust only distributes across fixed instances.

* Actual API and verification

ABI 16 operation 26 configures lease caching, with an exact mode receipt through
=configure_scheme_service_lease_plan_on=. Existing operation 24 retains the older
handler-selected experiment. =SchemeLeasePlanObservation= observes future short
and bulk permissions through operation 27; =SchemeWorkPlanObservation= reports
whole/sliced plan counts. Configuration and observation occur outside timed
windows. The default work policy is off; completion-policy changes still reset it.

Native controls exercise cold-layout rejection, unstarted dispatch, queue arrival,
ready/harvest invalidation, frozen 48-record late-arrival bounds, actual short
execution before the next bulk activation, whole/sliced release accounting,
multishot reentry, exception unwind, disabled/smaller replacement-policy isolation,
retained typed roots across callback/GC, and existing cancellation/expiry/close.
Final native teardown requires independent root/capacity retirement and zero roots.

The existing Runtime model is refined, not duplicated. Atomic cache updates,
grant snapshots and selected computation are separate states. A witness inserts a
short arrival between grant snapshot and handler selection, preserving the one
already-granted whole span and requiring a short opportunity before extension.
Another witness follows ready -> harvest -> independent result retirement and
restored bulk permission. A required stale-cache mutation must violate safety.
The model abstracts scheduling availability separately from GC and OS pauses;
it cannot establish a wall-time SLO or native speed.

** Remaining architectural cost

The work-policy queue scans and repeated layout/owner validation have moved out
of the handler body. The whole path no longer creates a checkpoint procedure or
writes then flushes per-span fuel. Event publication is atomic with invalidation,
and grant permission has an explicit frozen-span boundary. These are implemented
protocol changes, not a claim of admitted performance.

The current wrapper still creates continuation-safe activation state: mutable
span, normal-return, first-report and optional-checkpoint bindings captured by
wind callbacks. Cold layout descriptors do not eliminate that activation state.
Source shape identifies it as a remaining cost candidate; this capture does not
quantify its allocation/CPU share or establish it as the dominant bottleneck.
Future work should separate reusable immutable grant/compiled-executor metadata
from activation-local unwind/completion obligations. Reusing one mutable actor
frame across retained multishot continuations would be unsound. Any reduction
must preserve policy identity, original selected bounds, exception cleanup and
independent item completion/retirement. Merely moving bookkeeping to release or
choosing a larger threshold is not sufficient proof of a faster library.

Do not attribute the mixed tail to GC, OS scheduling, the new heartbeat repair or
activation allocation without matching causal evidence. Stage wall intervals
can overlap and their pooled quantiles are not additive. The current capture
fails performance admission. Keep this implementation uncommitted; do not run
the combined protocol publication gate on the strength of isolated tail wins.
Historical watchdog failures remain open despite the dedicated control pass.
