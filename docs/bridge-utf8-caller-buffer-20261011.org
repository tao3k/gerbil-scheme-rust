* Official-source algorithm and ownership

The installed SDK's matching source, =lib/c_intf.c:1254=, implements bounded
character-to-byte conversion into caller-supplied storage. Its extended UTF-8
and newline normalization are not suitable for Rust strings verbatim. This
bridge keeps strict Unicode scalars, NUL preservation and four-byte UTF-8.
=gambit/string/string.scm:560= documents the count/allocate/fill alternative;
the earlier complete negative measurements in =bridge-value-conversions.md=
remain rejected, not replaced by this report.

The production owned-string path now reserves Rust capacity, queries current
Scheme character length, and encodes directly into that stable allocation.
It removes the temporary Scheme bytevector payload, result-root insertion/
release and subsequent bulk copy. It still performs encoding and complete
SIMD UTF-8 validation; this is not literal zero-copy or cached text.

The two destination routes share one production strict scalar codec. A leaf
admits at most 256 characters and cannot allocate, callback or poll. Scheme
body pointers are reacquired at each leaf and never retained across polls.
The caller-owned Rust allocation remains stable throughout the synchronous
call. The source remains rooted and owner-affine. Only successful completion
admits the initialized prefix; an error may write a prefix but never publishes
its length or an unchecked String. Explicit Scheme bytevector snapshots keep
their independent root lifetime and existing behavior.

Capacity tradeoff: the fixture requests 13,660 Rust bytes for an 8,196-byte
result, instead of a compact 8,196-byte owned destination. The allocator may
reserve more than requested. Long-lived retained Strings can therefore cost
more memory; no peak-RSS or universal workload improvement is claimed.
Pointer-wrapper allocation remains possible; this is not zero Scheme allocation.

* Actual owned-string and local contracts

Independent actual =RootedSchemeString::to_string()= receipt:
=just bridge-benchmark buffers::utf8_fresh=, full twenty samples each.
Medians are 15.21 ms / 156.3 ms / 2.498 s, with ranges 6.507--79.87 ms /
99.49--421 ms / 1.216--5.343 s. This is another 2,220,000 fresh transfers,
not a matched acceleration claim against earlier independent runs.

The normal archive's root/span contracts, eight runtime unit checks, forty
safe-surface gates, twenty-one AOT unit checks and twenty AOT contracts pass.
Existing one runtime and five AOT ignored controls are unchanged. The new
root-span fixture initially used a nonexistent typed-string token accessor;
it was corrected to acquire/release its own raw roots through the existing
ABI, without adding a public accessor or suppressing a test.
The final Clippy pass also rejected a 109-line test helper; root acquisition
was factored into a named helper rather than allowing the lint.
Final workspace and actor-AOT all-target Clippy pass with warnings denied.
Production Scheme Unicode/mutation/bounds/root-GC conformance, frozen-control
conformance, generated SCM provenance, all-target check, formatting and the
filename gate pass. The released-root regression passes after the helper
refactor. No correctness, build or lint failure remains locally.
