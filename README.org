#+title: gerbil-scheme-rust
#+options: toc:nil num:nil

In-process Gerbil Scheme FFI and AOT build support for Rust. Scheme owns its
numeric tower, object identity and GC; Rust gets explicit, lifetime-bound
handles and whole-value transfer APIs.

This is a standalone bridge, not an application runtime or parser.
Marlin, POO Flow, Orgize, graph execution and application policy remain
downstream concerns.

* Native Scheme execution with Rust dispatch

Scheme application code follows Gerbil -> Gambit C -> native compilation.
Rust owns host admission, cross-instance dispatch and lifecycle. The default
Python ledger backend starts four complete Scheme runtimes on fixed OS owners.
Scheme retains macros, GC, closures, continuations and Actor/green-thread
scheduling. Tokio and Rayon submit jobs; they do not schedule Scheme continuations.

The former Scheme-to-Rust IR compiler and VM-free subset examples are removed.
The ledger's =rust-backend= selects native Scheme instances. Native typed values
and owner-affine handles preserve actual Scheme objects; no subset fallback
replaces their execution. See [[file:docs/hybrid-execution.md][the execution contract]].

The latest matched read-only payload-reuse baseline is 10.10x Actor-item
throughput with scheduled short-request p99 72.045 ms. This is a bounded
observation, not a universal speedup or fixed acceptance threshold. Read
[[file:docs/30-39-status/30.19-owner-resident-payload-baseline.org][the baseline]] and
[[file:docs/30-39-status/30.20-scalar-projection-experiment.org][the rejected projection experiment]]
for conditions and negative results. The private-image API is experimental on
Darwin; portable packaging, hot unloading and crash containment need separate
qualification. Raw diagnostic logs and experimental patches stay outside this
repository; maintained tests and English summaries are versioned.

* Runtime and ownership

- =GerbilRuntime= initializes the process-global runtime on one owner thread.
  Strong roots keep Scheme objects alive; handles cannot cross threads.
- Rooted snapshots retain an entire collection or component span with one
  root. Borrowed references cannot outlive that snapshot. Explicit element
  roots remain valid within the runtime lifetime after snapshot release.
- Byte/string/numeric/name buffers own their copied Rust data. Reused
  staging preserves published output when validation fails. No borrowed
  Scheme heap pointer becomes a Rust slice that survives GC.
- AOT and FFI work together: the canonical build produces linked Scheme
  objects; Rust enters those compiled exports through the C ABI.
- The separate =Gerbil= toolchain API explicitly invokes the configured
  interpreter/compiler. It is not a process fallback for in-process calls.
- Tokio controls admission, queues and response tasks. Concurrent Rust
  callers do not establish parallel Scheme execution inside one VM.

Multiple-VM capability does not imply multiple active processors or safe
cross-thread entry. Current CI explicitly SKIPS Scheme multi-processor
qualification because its pinned SDK lacks qualified multiple-threaded-VM
support. A skipped gate is not a pass. Independent-VM experiments remain
separate from the admitted single-owner path.

* Data transfer

| Family | Public transfer and ownership |
|--------+-------------------------------|
| Boolean, fixnum, character, flonum | Validated owned scalar spans, including trusted false/zero |
| String / bytevector | Whole UTF-8/byte transfer; validated owned Rust data and reused output |
| Exact integer | Canonical sign + binary magnitude, no decimal serialization or truncation |
| u16/u32/u64, s8/s16/s32/s64, f32/f64 vectors | Sealed native-layout whole spans with transactional staging |
| Symbol / keyword | Owned bulk names; spelling is not identity; explicit interned/uninterned construction |
| Pair, proper list, generic vector | Strong shallow snapshots and root-bound element references |
| Rational / complex | Whole batch construction; exact or inexact components remain rooted Scheme values |
| Gambit hash table | Explicit eq?/eqv?/equal?, strong keys/values, shallow bulk key/value snapshots |

Rational reduction and complex-to-real normalization follow official Scheme
semantics. Table order is unspecified; duplicate keys follow the selected
equality and last value wins. Weak tables, arbitrary Gerbil HashTable
implementations and deep recursive Rust serialization are not implied.

#+begin_src rust
use gerbil_scheme::{GerbilRuntime, NumberKind, RootedObjectBatch};

fn main() -> Result<(), gerbil_scheme::NativeError> {
    let runtime = GerbilRuntime::initialize()?;
    let numerator = runtime.root_value(runtime.fixnum_value(6)?)?;
    let denominator = runtime.root_value(runtime.fixnum_value(-4)?)?;
    let values = runtime.number_batch(
        NumberKind::Rational, &[(&numerator, &denominator)],
    )?;
    let mut parts = RootedObjectBatch::default();
    values.copy_number_components(NumberKind::Rational, &mut parts)?;
    drop(values);
    // Scheme normalized 6/-4 to -3/2. The snapshot retains both components.
    println!("{:?}", parts.get(0).unwrap().scalar()?);
    Ok(())
}
#+end_src

** Arrow C Data

Enable the Rust =gerbil-scheme/arrow= feature to exchange native Arrow arrays
and record batches with an initialized AOT Scheme owner. Build the Scheme
module through the ordinary =build.ss= package entrypoint and import
=:gerbil-scheme-rust/scheme/arrow=.

- =ArrowBatchExport= and =ArrowArrayExport= retain the Arrow buffers for the
  duration of a synchronous =bind_arrow_export= call. The Scheme view expires
  when the call returns or raises.
- =gerbil-rs-arrow-ref= projects Arrow nulls, primitive values, decimal and
  temporal values, text and binary, nested containers, unions, dictionaries
  and run-end arrays. The schema view exposes the original format, field
  name, flags and metadata. Temporal values use exact ticks in the schema's
  unit, and decimals become exact Scheme numbers. The null sentinel is
  distinct from a valid =#f=.
- =bind_arrow_producer= accepts an AOT producer that initializes owned
  =ArrowArray= and =ArrowSchema= descriptors. A Scheme producer can use
  =gerbil-rs-arrow-output= and =gerbil-rs-arrow-export-physical!= to supply
  a schema-directed layout with homogeneous Scheme vectors. The SDK copies
  those vectors into C-owned storage. Rust imports that storage through
  Arrow's native C Data importer. The producer's release callbacks must
  remain usable after the Scheme owner exits and on a Rust consumer thread.

The handoff shares Arrow buffers. Projecting a string, bytevector or nested
cell into an ordinary Scheme value materializes that value. Application
mappings for Scheme-specific objects such as symbols, procedures, rational
numbers outside a declared decimal scale and arbitrary hash tables need an
explicit Arrow representation.

Run the native SDK round trip with
=cargo test -p gerbil-scheme-qualification --features arrow-aot --test linked_arrow --locked=.

* Compiler observations and diagnostics

=gerbil-scheme-aot-build= owns generic Scheme/C compilation, optimization, ABI,
archive generation and compiler subprocess output. Application =build.ss= files
own their PackageSpec/module graph; consumer process glue owns neither compiler
flags nor direct command replay. Gerbil Scheme is the toolchain; this integration
project does not create an additional SDK authority.

Live compiler output is framed at actual pipe reads: an incomplete diagnostic
chunk receives a newline delimiter so Cargo can expose it before child exit.
Complete lines are unchanged; empty reads emit nothing. Framed diagnostics retain
the payload but are not a byte-identical original stream. Phase observations and
output bytes are not successful exit, quiescence or runtime execution permission.
A silent child remains subject to the original outer idle/wall limits.

=GERBIL_BUILD_VERBOSE= enables live compiler observations. Detailed optimizer
notes and allocation dumps require =GERBIL_BUILD_COMPILER_DIAGNOSTICS=1;
=GERBIL_BUILD_OBJECT_PROGRESS=1 independently selects compiler-written allocation
artifact observations. Diagnostic flags do not alter optimization or ABI policy.
No wall-clock, CPU-time or input-read heartbeat is emitted.

The Rust Cargo handshake test blocks a compiler child until the outer Cargo
reader observes its unterminated diagnostic payload. The child retains a
five-second bound and exits naturally after acknowledgement. Failure and empty
output controls remain separate from archive/runtime acceptance.

* Build and validation

Cargo owns Rust packages and dependency resolution. =build.ss= owns Scheme
compilation; the AOT build helper owns compiler discovery, archive production,
provenance and complete link receipts. Bazel owns the cross-language CI graph.
Downstream consumers validate and consume the receipt, without repeating
Gerbil installation, compiler or system-library discovery.

Compiler selection follows the configured Gerbil executable and its paired Gambit compiler.
Ghostscript's unrelated =gsc= is rejected. Explicit =GERBIL_GSC= overrides
remain validated. OpenSSL, zlib and SQLite link receipts are admitted before
generation; missing required libraries fail the producer build.

Use the installed Gerbil environment and repository's Justfile:

#+begin_src text
just bridge-workspace
just bridge-lint
just bridge-actor-lint
just bridge-regenerate
#+end_src

Regeneration is required after Scheme/build-input changes; fingerprint
validation prevents stale committed SCM from qualifying a new source.
Linux/macOS CI keeps Cargo, single-processor Actor/AOT, Rust concurrency and
=bazel test //:ci= mandatory. SMP is a separately labeled unsupported gate.

The [[file:.github/actions/setup-gerbil/action.yml][shared setup action]] supplies immutable CI SDK prerequisites.
Consumers pin that action to a commit, rather than copying its installer.
The local benchmark workflow does not download or rebuild the installed SDK.

The default runtime exposes package build/test through its =build= module
and the existing C ABI. The =external-program= profile retains consumer-owned
programme linking. =GerbilRuntime::build_package= loads ordinary
=build.ss= and invokes its native main; =test_package= runs native GxTest.
Transport status and the tool result are separate: a returned 42 is a failed
GxTest run, not admission. Calls remain on the runtime owner thread and use
native Gerbil child-process handling for their duration; use the existing build
host without concurrent unrelated host children. No Gerbil CLI is launched to
dispatch these operations. SDK bootstrap still uses the ordinary native builder.

The same boundary compiles an existing =build.ss= declaration through native
=std/make= and calls the existing programme/resource-closure producers. Metadata
imports use the existing rooted Scheme object ABI. These calls introduce no
Rust Scheme-expression planner or string-array request protocol. The existing
programme metadata observer still owns its separate native GxI subprocess;
build/test dispatch itself remains in the caller process.

Downstream Cargo checks use =just bridge-cargo= with the standard SDK
configuration. Library link flags come from =build.ss=
the =std/make= pkg-config helpers into the existing compiler graph; Rust validates the receipt
without another host package probe.
