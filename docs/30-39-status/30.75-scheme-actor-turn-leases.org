* Ownership protocol

An Actor worker selects turn behavior once, using the existing Scheme policy.
ABI19 parameterizes a private turn record and obtains one outer execution lease.
The record contains its budget, policy identity, creator Scheme thread, active
invocation span sum, consumed reservation and mutex-copied class permission.
Only the private constructor publishes a record to that parameter. Typed reads
rely on this module-owned invariant; public layouts/configuration remain checked.

An item retains its dynamic-wind callbacks and frozen plan. When its Scheme
thread already owns the same-class lease, entry/exit adjust existing lease depth
without another mutex/queue transaction. Otherwise entry uses normal acquisition
and final exit uses normal locked release. Retaining item winds is necessary:
continuation reentry/escape can cross item boundaries independently of the turn.
No invocation-normal flag, mutable activation pool, global thread registry or
Rust green-thread executor is introduced.

| Boundary | Scheme authority | Independent obligations |
|----------+------------------+-------------------------|
| Turn entry / reentry | Acquire outer lease; restore this thread's reservation from active spans | Does not select an item plan or retire a result |
| First item entry | Select immutable plan once; reserve selected span | Selection is not successful execution |
| Item reentry | Retain original plan; reserve another dynamic execution opportunity | No duplicate plan-selection report |
| Successful whole return | Accrue declaration through ABI18 epoch-fenced accounting | Not a root/capacity acknowledgement |
| Sliced checkpoint | Existing owner/class/span validation and bounded accounting | Does not claim the unreported suffix |
| Item exception / escape | Decrease borrowed depth and active span; consumed reservation remains | No whole-success credit, no quota refund |
| Existing Actor quantum yield | Suspend complete lease, let Scheme schedule, reacquire | Does not settle dispatch or native completion merely by yielding |
| Internal await / work handoff | Same suspension protocol; active declarations survive the new grant | Pending suffix cannot be counted as a new empty grant |
| Turn exit / exception | Locked outer release settles accumulated work and grants queued peers | Each result still independently owns root/capacity retirement |

* Remaining work and short execution opportunities

Remaining execution permission is distinct from admission charges and successful
work totals. Each entry consumes its selected span, including a failed item.
Before a following item would exceed permission, Scheme creates an execution
opportunity. This applies even when Actor quantum is zero. First selection after
that opportunity observes the new grant permission; an existing continuation
keeps its original immutable bound. There is one opportunity, not a retry loop
waiting for a smaller policy to permit an old larger span.

The receiving Scheme thread publishes its permission/reservation only after
acquisition confirms it owns the lease, while still under the acquire mutex.
A releaser may select another thread, so grant selection cannot use the
releaser's parameter context to update the receiver. Each turn has independent
state. During suspension its active item span sum is retained; reacquisition
conservatively reserves that sum. An exceptional suffix therefore cannot refund
its opportunity and allow another whole item without a boundary.

The existing Actor quantum and class arbitration are unchanged. Original Actor
yields now suspend the outer lease; holding it across thread-yield would prevent
a competing short thread from acquiring it. Direct short requests retain their
own item extent and do not enter an Actor batch barrier. Fresh items cannot turn
8 x 48 declarations into a single uninterrupted batch grant.

An old retained span can exceed a newly contended permission. Nested arbitrary
Scheme handlers can also contain additional declared work. These remain explicit
cooperative bounds, not hard wall-time or arbitrary-code preemption guarantees.
No language feature is disabled to recover performance. A continuation transferred
to another Scheme thread cannot mutate the original thread's reservation record;
it uses a conservative yielding acquisition path. Inherited or stale contexts
cannot authorize borrowing a different thread/policy. No VM/root travels across
Rust owners. Native completion/progress identity remains governed by the existing
completion model and idempotent progress ledger, not by a turn's CPU reservation.

At quantum1 the current workload still releases between every pair of items.
Consequently fewer grants cannot be assumed. This candidate tests whether the
remaining depth/mutex/extent rearrangement helps; it does not claim batch-wide
amortization. The extra turn state and suspension winds are real candidate costs.

* Actual API and reused Runtime model

=configure_scheme_service_actor_turn_on= configures idle ABI19 operation30 with
exact mode4 receipt and existing =SchemeWorkExecutionPolicy=. ABI18 operation29
remains the same-image control. =call-with-gerbil-rs-service-turn= is the actual
Scheme API used by Actor workers; its callback receives a nullary yield operation.
The diagnostic =gerbil-rs-service-turn-snapshot= reports reservation, active span,
permission and depth; it grants no execution, native root or capacity authority.
Canonical std/build includes the new file in extra-inputs. No Bash or independent
Python build path is introduced.

The existing Runtime activation state adds turn ownership, consumed reservations,
permission and suspension. Its prior successful-work and root/completion state
remains authoritative. Reservation accounting is independent from actual success.
Witnesses cover failed item then another item, suspension with an outstanding
span, repeated turn reentry and exceptional replay, real short dispatch/start /
execution while the turn is released, and accepted close/drain. A suspended turn
must not own the CPU; a different short worker may own it. Mutations must reject
refunding a failed execution reservation and declaring a yield while retaining
CPU ownership. The existing seeded bounded domains are reused, not replaced by
a new unrelated model. Finite success is not native or performance acceptance.

Native controls invoke the same public turn/work APIs inside the actual image:

- Zero explicit Actor yields, with a queued short peer between two bulk items.
- The same opportunity after an intentionally failing bulk item.
- Active span/reservation/depth before and after internal suspension.
- Failed whole work leaves no successful credit and does not refund permission.
- Successful and exceptional multishot turn reentry after the original extent exits.
- A parked bulk48 invocation, short peer holding the lease, and actual queued
  handoff back to bulk with new permission4; the receiver publishes its own state.
- Existing class/epoch/nested/GC/root/cancel/timeout/drain controls remain in the
  native suite, using the new Rust policy endpoint for actual Actor workloads.

The full Scheme runtime remains responsible for execution, Actor scheduling,
continuations, exceptions and GC. Rust only distributes across instances.
