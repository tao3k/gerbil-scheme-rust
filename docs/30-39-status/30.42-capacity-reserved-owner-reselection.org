=SchemeServiceRouter::new= and =SchemeRoutingAdmission::default()= retain
=Pinned=. The existing short/batch scoring and rotating tie order are shared
by both strategies. The optional strategy re-evaluates eligible owners until
one can provide the class quota, native work credits and native request slot.
It never reserves every owner concurrently or migrates accepted Scheme values.
Constructor validation captures the exact native capacity objects under one
admission fence. Reconfiguration invalidates old routers, including unassigned
waiters; old class quotas cannot silently cross into a new native budget epoch.
This applies even to equal numeric limits. A fresh router validates the new scope.

Returned types distinguish =SchemeRouteClass::{Short,Batch}= from
=SchemeServiceExecution::{General,Short}=. A short host route can intentionally
use general execution for the existing matched control. No payload-size heuristic
replaces the application's class declaration. Work, lane, execution and optional
trace declarations are sampled once before asynchronous admission; nonzero work
and the existing one-unit/stateless native-short constraint are validated.
Affine lanes still require explicit fixed-owner submission.

Per-owner =loads()= have explicit scope: pinned routing includes owner-specific
admission waiters; reselection charges an owner only after complete reservation.
Unassigned FIFO waiters are not attributed to any owner. Declared work is not
remaining CPU, elapsed service time, or a guarantee of short wall-clock latency.

* Reservation and wake protocol

1. Join one FIFO admission turn for the requested class. Short and batch classes
   have separate turns; newly arriving work cannot repeatedly overtake an older
   waiter in that same router/class.
2. Subscribe to the pool's versioned capacity-change channel before scanning.
   Mark the observed version, then rank live owners with the existing score.
3. Try one owner's class quota and native work/slot pair. If any credit is
   unavailable, release every temporary acquisition before another candidate or
   an asynchronous wait. Failed speculative scans do not notify themselves.
4. Once all credits are held, charge that owner and publish through the actual
   native Scheme service API. The existing exact Capacity Arc fence rejects a
   stale reservation after reconfiguration or pool close. Reserved work units
   are checked and preserved in native request metadata.
5. Native projection/root balance retires accepted work, then releases the
   work/slot guard and publishes usable-capacity change. Class/load retirement
   precedes that release, avoiding an early duplicate event while native credits
   are still unavailable. A rejected pre-publication path retains its FIFO turn
   until its guards have unwound.

The change channel is initialized only by the optional strategy and remains
active for that pool's lifetime. Direct native dispatcher completion, fixed-owner
reservation cancellation, reconfiguration, owner failure and pool close all
participate. A release between scan and wait cannot vanish into a transient
Notify event: the watch version records it. No Rust polling timer is introduced.
No Rust waker is invoked under the admission/close lock; legacy pipe failure also
releases its writer lock before notifying capacity waiters.

Cancellation while acquiring work needs particular care: Tokio can allocate
partial work internally before returning a complete owned permit. The RAII
guard exists before that await and notifies on cancellation even when its
explicit work field is still empty. The speculative nonblocking helper never
holds such a partial acquisition across an await.

Close wakes both class-turn and capacity waiters. Unpublished cancellation or
admission timeout unwinds reservations. Caller timeout/drop after publication
continues to retain native work and class charges through projection; it cannot
revoke a running Scheme task or release its roots early.

FIFO fairness is scoped to one router/class. An older large request can still
hold the class turn while a smaller follower would fit. Independent routers have
independent class quotas under shared native limits. OS/GC progress and arbitrary
uninstrumented Scheme computation remain outside any latency-bound claim.

* Reused model boundary

The existing =owner_lifecycle= model adds =selected= and =committed= owner maps.
Selection can change only before work reservation, producer staging or acceptance;
publication commits the owner. Existing per-owner credit, root and close safety
invariants remain in force. The original fixed-assignment =step= is retained;
=reselectionStep= adds pre-reservation selection, and an unsafe accepted-owner
move is a required negative control. No second lifecycle or Scheme scheduler
model is introduced.

Local typecheck, all 32 small-domain scenarios and 1,000 reselection traces at
64 steps passed. The post-publication owner-move mutation produced the expected
invariant violation. These finite checks do not prove Tokio FIFO internals,
watch-channel implementation, native correctness or unconditional progress.
The aggregate Rust model gate remains in the existing CI job. Router capacity
identity/epoch and watch internals are separate native/type refinement
obligations, not claims added to this abstract lifecycle state.

Capacity availability is not an owner-runnable or prompt-wakeup acknowledgement.
The remaining gap is after admission and before this probe's native construction.
It can include queued bulk construction/execution/GC, Scheme wait handling,
capacity-event synchronization and OS scheduling. These unobserved captures do
not isolate those causes. They do not establish that Scheme GC or the OS alone
caused the regression, and SDK process GC CPU must not be subtracted from owner
thread CPU. The failed wait-phase hint from 30.40 remains rejected.

The optional route closes demonstrated pinned-owner admission and quota-scope
problems, but it is not admitted as the final short-latency algorithm. Existing
native types and Scheme capabilities stay complete; defaults stay Pinned.
