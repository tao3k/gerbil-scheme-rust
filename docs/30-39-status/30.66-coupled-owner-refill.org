#+title: Coupled owner refill after native result retirement
#+options: toc:nil num:nil

* Evidence and protocol decision

This follows [[file:30.65-native-service-construction-pipeline.org][30.65]], retaining that experiment and all its negative results.
The previous comparison changed native construction and refill together. Its
CPU throughput gain was 12.24%, mixed throughput change was -2.42%, and bulk
construction p99 worsened in both workloads. Those observations do not isolate
the cost of either change or establish an OS/GC cause.

Offline analysis of the existing five paired AB/BA blocks gives CPU throughput
changes +14.574%, +9.482%, +6.943%, +11.353%, +12.345%. Mixed changes are
+21.812%, +32.816%, +12.016%, -5.946%, -2.240%. These block statistics differ
from throughput computed from the overall median duration; neither replaces
the other. The negative aggregate result remains part of the record.

The actual refill code treated every ordinary inbox message as a barrier. An
already-admitted service request, a payload-free wake and a lifecycle control
all discarded the remaining opportunities from that retirement cycle. Claiming
a shared short request also deferred it and ended refill. This is a concrete
protocol distinction missing from the implementation, not proof that it caused
the entire measured mixed regression or the construction tail.

The candidate couples source arbitration to the same bounded owner cycle. It
keeps the fused native constructor identical in both A/B arms, isolating this
change from constructor selection. No new Scheme ABI, constructor, scheduler,
capacity registry, timeout or default is introduced.

* Ownership and bounded service turns

| Boundary | Rule |
|----------+------|
| Ready snapshot | Project every harvested result; clear each native root/slot before returning that result's credits |
| Prepared input | At most one owned Rust request per owner, under original active/slot/work budgets; no new Scheme root or NativeSession |
| Cycle budget | At most one dispatch attempt per independently retired result; unused opportunities disappear at cycle end |
| FIFO service | Construct/submit the already-admitted head request in this turn, then retain the remaining opportunities |
| Pure wake | Consume one bounded turn, without constructing a value or abandoning the whole cycle |
| Control or arbitrary callback | Preserve it as the FIFO head and end refill; never cross this barrier |
| Shared short | After the inbox check, claim/submit one short request in this turn; keep remaining opportunities |
| Producer or offer | Reuse original preparation, reservations and revocable offer/entry fence |
| Next harvest | Return to Scheme's native service cycle after the bounded turns; never recursively harvest while projecting |

Requests retain their independent slot and work permits. A turn is not a
capacity permit, cost estimate or time slice. A wake cannot allocate credits,
move an offer, create a Scheme root or reset a watchdog. Cancellation, deadline
and close are rechecked at the original prepared/offer entry fence. Cancellation
may consume an attempt without constructing; no replacement attempt is minted.

All ready slots retire before fresh native construction. Native failures keep
the existing per-result retirement/drain protocol. Closing joins native children
before releasing held drain credits. The native scheduler still decides Actor,
green-thread and continuation execution inside each fixed owner runtime.
Arbitrary constructors and GC can exceed a dispatch turn in wall time; this
protocol does not claim preemption, a hard latency bound or starvation freedom.

* Actual library API

#+begin_src rust
dispatcher
    .configure_scheme_service_completion_on(owner, SchemeServiceCompletion::PipelineCycle)?
    .wait(timeout)?;
let enabled = dispatcher
    .configure_scheme_service_refill_on(owner, true)?
    .wait(timeout)?;
assert!(enabled);
// Submit through the existing typed service/stream/pool APIs.
#+end_src

The new configuration executes as an owner FIFO control. It rejects completion
policies other than PipelineCycle. Selecting any completion policy resets this
option to false, including selecting PipelineCycle again. Both the ordinary
Snapshot default and PipelineCycle's original refill remain unchanged unless
explicitly configured. Service ABI 11 and native policy receipt 5 are unchanged:
this is Rust admission arbitration, not a new Scheme execution mode.

* Native and model acceptance

The existing native suite exercises the opt-in on the PipelineCycle preparation
frontier and single-worker priority/retirement fixtures. Other policies reject
the new configuration. Continue/cancel/expiry/close tests retain the bound on
prepared input, prevent construction before full ready retirement, and check
credit/producer registration return, zero roots, joins and removed image files.
Existing generic Scheme/GC/continuation/exception controls also run; these are
native receipts, distinct from the finite model.

The existing owner lifecycle model adds a bounded notification turn to its
pipeline budget. Reused completion-domain witnesses show notification followed
by prepared entry, and notification followed by control/close with budget and
reservation drain. Sampled pipeline lanes include the new transition. Prior
no-retirement-credit, early-slot-credit, stale-token and preparation-overtake
negative controls remain required. This checks ownership/accounting, not native
performance, OS scheduling or an elapsed-time fairness guarantee.

The historical first-port watchdog exit remains UNATTRIBUTED with cleanup
UNVERIFIED: its failed image, last meaningful event and native frames were not
captured. Current failure reporting retains phase/last event independently of
libtest capture; diagnostic phase messages do not renew the five-second progress
deadline. A current pass cannot explain that historical failure.

* Results and non-promotion

The frozen run exits 0 in 6.426 seconds with 40 samples and no controller
expiry. Each arm/load projects 10,880 results. Every sample uses all four
owners, conserves published offers as withdrawn plus entered offers, and ends
with empty completion custody. Final cleanup joins four owners, reports roots
=[0,0,0,0]=, quiesces the services and removes their owned image files. This is
not an RSS soak or proof of unloading every native mapping.

The candidate does not demonstrate an overall performance improvement. CPU
throughput decreases 0.680%, its short native p99 increases 8.227%, and mixed
short native p99 increases 0.737%. Mixed admission, bulk service p99 and owner
finish spread improve, but short pending p99 worsens in both workloads. Harvest
group counts barely change (-0.218% CPU, -1.418% mixed); construction p99 remains
roughly 0.38/0.43 ms despite microsecond medians. Do not chain the earlier
12.24% gain onto this separate capture or dismiss negative changes as noise.

Minimum short overlap remains 42/42 CPU and 64/64 mixed. Actor peer minima are
1/1 CPU and 0/0 mixed. Minimum owner progress fractions are 0.987755/0.987448
CPU and 0.987952/0.987854 mixed; raw minima are 1936/1888 and 1968/1952. These
bounded observations do not establish universal starvation freedom.

as the preceding capture. Constructor selection cannot explain differences
between these two new arms: both use exactly the same fused path. This rejects
the claim that correcting inbox/short refill barriers alone solves the
construction tail or guarantees preserved CPU throughput. It does not prove
the tail is purely GC, allocation, OS runnable delay or native task execution.

The next architectural boundary is native construction/allocation interacting
with Scheme's service cycle. Any proposal there must account for input graph
ownership through Actor completion and projection, and preserve generic
constructors and complete Scheme execution. Neither a Rust dispatch threshold
nor relabeling constructor wall time supplies that protocol. The new refill
option remains explicit and unpromoted; the current native pipeline and all
ordinary defaults stay as before.
