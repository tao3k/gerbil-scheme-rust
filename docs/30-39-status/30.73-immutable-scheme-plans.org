* Necessary state versus duplicated representation

The actual O2 Gambit-generated C for the previous cached path explicitly allocates
four boxes and three wind closures on each invocation. The boxes retain selected
span, normal return, first report and checkpoint. This is compiler evidence of
representation cost, not proof that it dominates the previous p99 or CPU change.

| Data | New owner / lifetime | Why retained |
|------+----------------------+--------------|
| Policy identity, declared cost, selected bound, checkpoint procedure | Read-only plan descriptor | Reentry must preserve the original bound and cannot charge a replacement policy |
| Latest descriptor set keyed by policy | Application layout, one published entry | Avoid rebuilding equivalent metadata and sliced checkpoint closures |
| First selected descriptor | One invocation-owned activation | Must survive continuation capture and cannot be pooled across invocations |
| Normal-return marker | Activation, reset on every dynamic entry | Exceptional replay must not inherit a prior successful return |
| First-report marker | Activation, cleared after first exit | Reentry cannot create another plan-selection report |
| Actual lease owner, class, depth, ready/dispatch obligations | Existing Scheme budget | Shared across green threads under the existing ownership protocol |
| Result IDs, roots, retained capacity | Existing independent completion protocol | Metadata and activation flags cannot refund or retire them |

The new path uses one private activation record in place of four independently
boxed variables. Its descriptor contains no mutable invocation flags. The three
wind callbacks remain because lease entry/exit must run for exceptions and full
continuations. No global interrupt disabling, linear-only continuation restriction
or Rust replacement execution is introduced. Generated Scheme infers the fresh activation type. The private token builder also
establishes the immutable descriptor type; typed accessors inside the activation
wrapper avoid repeatedly validating that same descriptor. Public layout/config
validation remains checked. Actual code generation and native qualification must
verify this representation before performance claims.

* Metadata publication and reuse

A layout holds one fully formed cache entry keyed by the policy object. Its four
slots cover bulk/short and maximum/contended permissions; equal spans can reuse a
descriptor. Whole descriptors have no checkpoint. Sliced descriptors share a
stateless procedure bound to budget, policy identity, class and span. All mutable
work/queue state remains in the existing budget, never in the descriptor.

A cold miss constructs a complete entry before atomically publishing its pointer.
An interrupted cold construction may duplicate equal metadata; it cannot publish
fields from two different policies. This is not a claim of globally unique object
identity. A stable sequential hit reuses the published entry. The layout slot
holds at most one entry, rather than an unbounded policy map. Displaced entries
are collectible unless retained by live activations/continuations. A latest old
entry may remain cached until layout reuse or VM destruction; this is bounded
cache retention, distinct from per-call state growth or an external root leak.
Application-created layouts and deliberately retained continuations have their
own lifetimes; their retained Scheme heap is not silently discarded.

Grant permission is still copied under the existing Scheme mutex. Already selected
48-record work retains that bound across late arrivals. Future grants observe
pending, queue and ready-generation invalidation. Contended permission remains
four records. Neither descriptor reuse nor cache replacement rewrites an active
span. Original Actor quantum, cooperative opportunities, admission charges and
result-retirement ownership remain unchanged.

* Reentry, exceptions and nested ownership

Each invocation allocates its own mutable activation record. Reentering its
continuation reacquires the lease and resets its normal marker, but retains its
immutable descriptor. Multiple successful returns charge the retained declaration;
that conservative logical-work count is not exact CPU work during partial replay.
An exceptional or escaped unfinished return does not get whole-body credit.
First-report state belongs to the invocation and is not reset on reentry.

Different invocations may share a descriptor/checkpoint procedure. They cannot
share normal/report flags. Native controls suspend invocation A, complete B, then
raise inside A without exiting A's outer dynamic extent. A must not receive B's
normal credit. Another control successfully resumes a continuation and then
resumes it exceptionally; the latter must not inherit the successful marker.

A lower-level suspension gap was found during ownership audit: resume always
reacquired a lease even after its class budget was disabled, while outer unwind
skipped release at zero limit. Resume now follows the same positive-limit guard.
A native parked-unit control disables both budgets before resume and requires
idle ownership afterwards. The actual Rust endpoint already rejects policy
configuration while jobs are active; its guard is preserved. This distinct
protocol control does not attribute historical watchdog failures.

Same-class nested invocations keep independent flags and preserve depth. A nested
parameterization cannot relabel an already-owned lease to another class; the
failed attempt releases its mutex without changing the original owner/depth.
A saved bulk checkpoint cannot charge a short-class lease. These checks apply
at lease acquisition or sliced checkpoints, not each whole-body record. Declared
layout bounds remain a cooperative application contract; arbitrary nested or
unreported work is not hard preemption or a wall-time guarantee.

Replacing/disabling the work policy changes identity. Old continuations retain
their old selected bounds, but cannot add work or plan counts to the new policy.
This does not make old code satisfy a smaller replacement bound. Existing item
completion remains idempotent and every result independently retires its root
and retained capacity. Rust only distributes across fixed VM owners; complete
Scheme execution remains inside Scheme.

* Actual API, reused model and directed gates

=configure_scheme_service_activation_plan_on= configures ABI 17 operation 28 and
checks its exact mode receipt. Existing ABI 16 lease-cell mode is retained as the
matched control. Both use =SchemeWorkExecutionPolicy= and existing native types.
Opaque Scheme metadata identity is diagnostic, never a root/capacity authority.

The existing Runtime model adds invocation ownership to the same CPU/root state.
Its bounded witnesses cover shared logical metadata, independent nested flags,
repeated reentry, successful-then-exceptional replay, smaller policy replacement,
and close/drain. Two concrete mutations must be rejected: crediting A using B's
normal marker, and crediting a stale-policy return to the replacement epoch.
Finite model success is neither native allocation evidence nor a performance SLO.

The same-image workload handoffs also differ (CPU 500 to 412, mixed 542 to 562).
Faster construction can change arrival overlap and therefore permission/lease
transitions, despite equal conserved logical work. These observations do not
prove a GC, OS wakeup or bookkeeping bottleneck. Stage quantiles overlap and
cannot be subtracted to infer one. CPU utilization was not measured here.

The next protocol decision must separate immutable lookup/activation storage
from executed-work reporting and lease-release obligations: invocation normal
and first-report markers remain private, checkpoints retain epoch/class fences,
and each result independently owns its root/capacity retirement. Dynamic-wind
callbacks cannot be deleted or activations pooled to recover throughput. Before
another candidate, establish which service-cycle transition can own accounting
without delaying short execution/completion or requiring per-handler checks in
an uncontended whole-body plan. The current result rejects storage reduction as
a complete solution; it does not authorize a new attribution or threshold tweak.
