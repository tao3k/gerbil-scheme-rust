#+TITLE: Running-owner short admission and the retained benchmark baseline

* Library behavior

=SchemeServiceRouter::with_owner_claimed_shorts= opts into the existing bounded
shared short source. A running owner claims each stateless short request before
native construction and acquisition of its active native charge. A request no
longer reserves an owner that cannot run while an eligible peer is available.
The configured owner set and short quota must match the existing short pool.

Rust only admits and distributes work across fixed owners. Gerbil Scheme keeps
the complete evaluator, Actor and green-thread scheduling, GC, exceptions and
continuations. Native typed inputs and owned Rust projections remain in use.
Batch routing, stateful owner/lane affinity and defaults are unchanged.

Before claim, cancellation or timeout removes queued Rust input. After claim,
client timeout does not release native quotas or roots; the owner must complete
projection and retirement. Router clones share the short facility, including
its explicit close boundary. The native witness holds one owner, verifies that
a peer completes short work, and checks cancellation, post-claim timeout and
close/drain with zero transient roots.

environment was not captured. No host, GC or OS attribution follows from this.

* Rust reproduction entry point

Use the frozen executable for an exact artifact replay. To build from source,
use the existing project SDK/toolchain environment and Cargo bench target:

#+begin_src sh
cargo bench --offline --locked -p gerbil-scheme-qualification \
  --features arrival-clock --bench scheme_service --no-run
#+end_src

Set =GERBIL_SERVICE_BENCH_IMAGE= to the verified retained image. Invoke the
executable with the following arguments; the target is its second arm:

#+begin_src sh
--progress-fair-ab --fixed-short-selective --completion-service-ab
--supply-cycle-ab --capacity --capacity-owners=12
--capacity-rust-workers=12 --capacity-clients=50 --capacity-owner-claim-ab
--capacity-count=1000000 --capacity-seconds=30
--capacity-warmup-seconds=5 --capacity-rate=14639
#+end_src

The arrival clock, workload, native calls, quantiles and outcome accounting
remain Rust-owned. No Python benchmark runner is required. Native inactivity
and request deadlines remain five seconds; the external replay limit is 300
seconds. No machine-specific path, raw log, image or executable is committed.

* Integration and retained negative results

PR integration retains the later atomic private-directory reservation fix and
the three-worker model gate. The merged source therefore differs from the
frozen checkpoint in those integration details and formatting. Its exact-head
CI is a separate obligation; the frozen measurements are not relabeled as
measurements of a newly compiled integration executable.

Three full integrated model invocations exceeded the existing fifteen-minute
budget. Fixed worker groups and module scoping alone were insufficient: the
last attempt completed 82 checks while pending work remained bound to busy
groups and another worker was idle. The installed Quint 0.33 CLI
sends its complete lookup table to a new Rust evaluator for each test; the
canonical parsed artifact is approximately 34 MiB across thirteen modules.

The existing Rust gate now asks the pinned Quint parser for module identities,
imports and source ranges once. Each check receives the complete transitive
module closure for its explicit main module, copied byte-for-byte from the
single canonical model. No declarations within a required module are removed.
The whole canonical file is still typechecked, and its digest is rechecked
before every scoped invocation. Missing dependencies, external source ranges
and changed canonical input fail closed. Private temporary closures are owned
through the scoped workers; no generated model copies are committed.

Only the input file passed to each main-module check changes. Command mode,
main, initializer, step, invariant, seed, sample bound, step bound and rejecting
controls remain intact. The complete existing check plan is now collected
before execution into a finite shared queue. A worker claims one owned check
only when ready, runs its original success or counterexample assertions, then
claims another. Long scenario commands are scheduled before shorter runs.
No result is inferred from planning: the gate asserts that every planned
check completed, and scoped thread panics still fail the entire gate.

The three-worker ceiling and fifteen-minute budget remain unchanged. Four ordinary Rust controls cover exact module retention,
missing dependencies, source positions and cache invalidation. The failed
invocations remain outside Git. There is no new model, interpreter or Python
runner, and no change to Scheme execution or benchmark timing.

The final complete real Quint gate passes all 95 planned checks in 714.76
test seconds, within the unchanged 900-second external limit. The initial
canonical typecheck also passes. Merged library tests pass 51 cases; native
service qualification passes all four selected executable cases. The four
projection ownership controls, strict selected-target Clippy and workspace
formatting also pass. These are local source/functional checks; new-head remote
CI remains separate, and they do not create a new production latency claim.

The protected-client experiment reached 17.327301 ms short p99 and did not
preserve the retained working point. Its 33.741527 ms borrowed-policy control
was a new executable and the first arm, not the frozen binary's second arm.
That comparison cannot establish improvement over the frozen checkpoint.
The separate arrival-reactor experiment also failed to restore the earlier
tail. Neither candidate is included by this integration.

The next protocol work must distinguish retractable Rust inputs, irrevocable
native work and completed results still owned by clients. Client admission
credits and native root/credit retirement are separate domains. Reuse the
existing model before changing their transfer boundary; do not free roots
early, introduce unbounded result retention or tune a reservation count as a
substitute for the ownership protocol.
