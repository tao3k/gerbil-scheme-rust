* Real Scheme workload and matched results

Each batch contains eight complete order-summary requests. Rows contain category,
quantity, unit price and a Unicode label. Native Scheme parses JSON bytes,
collects while the parsed tree is live, validates rows, aggregates integer totals
by category, counts characters, sorts keys and serializes JSON bytes. The Rust
oracle is used only to assert exact totals, row/character counts and every group.

A has one fixed owner/instance. B has four. Both receive the same eight inputs
per load, so total input rows and application work are equal. A executes requests
sequentially; B dispatches them across four independent single-processor instances.
Each measured request forces GC in either variant. Five distinct GSTATE addresses
and one actual processor per instance are asserted across the live A/B pools.

Ten ABBA blocks per load give 20 complete samples per variant, 120 measured
batches, and 960 individually checked measured responses. Medians average the
two middle samples. Timings include request cloning, bounded admission, native
input conversion, Scheme work and GC, result copy/root release, host response
wait and oracle validation. Corpus construction and pool initialization are outside
these steady-state samples. Each pool is warmed with one complete batch per load.

* Executed contracts

- Save a Scheme continuation, return through the real library byte/root call path,
  force repeated GC and resume it twice on its original owner. Verify retained
  vector contents, Scheme thread identity, dynamic parameters, dynamic-wind
  balance and the Scheme exception path.
- Clean up and join one instance while another retains its continuation; resume
  that survivor and compute again. Also clean up a VM still holding a saved
  continuation in Scheme globals. This does not prove finalizer or leak freedom.
- Reject ordinary linked runtime initialization after selecting image mode.
- Use four concurrent Rust callers through Send + Sync dispatcher clones; reject
  every clone after the owning pool closes admission.
- Reject a full finite queue, invalid owner, invalid owner count and oversized
  request before admission. Reject oversized replies while releasing transfer roots.
- Observe a request timeout and a shutdown deadline while Scheme is still live.
  The first shutdown reports one pending/unjoined owner with no cleanup receipt.
  Later observe both accepted results and a complete clean shutdown. Timeout is
  not cancellation; no active VM is destroyed from the host thread.
- Drop a result ticket while its accepted Scheme delay runs. Later queued work
  completes and the final transfer-root count remains zero.
- Reject malformed JSON as a Scheme exception, then call the same owner again;
  input/result roots are balanced on rejection and conversion failure too.
- Reject a missing export before native setup. Startup errors retain the cause
  and observed cleanup/join state. Partial native setup rollback is not qualified.

The native gate retains its five-second real-progress/startup/response checks.
Fresh child execution has a stricter four-second kill/reap gate. Neither is
extended to manufacture a passing run. Image code is retained until process exit.
Dropping a busy pool detaches owners and does not certify completed cleanup;
explicit shutdown is required for clean receipts.
