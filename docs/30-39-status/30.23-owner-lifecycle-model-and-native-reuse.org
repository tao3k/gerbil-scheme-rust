#+TITLE: Owner lifecycle model and native OS boundary repairs
#+STARTUP: overview

* Decision

Add a narrow Quint protocol extension to the existing handoff model, and keep native acceptance independent. The new model covers late publication, lazy executor recreation, owner-bound handles, observation timeout and close/drain/retirement. It does not reimplement Tokio, Rayon, Scheme GC, Actors, green threads or SMP scheduling.

The original two native blockers are diagnosed and repaired at the OS directory boundary. A separately reproduced host-signal crash is repaired at native setup/cleanup. The identical 600-second reuse and eight-cycle lifecycle targets now complete on the repaired O2 artifact. This is finite native acceptance, not industrial endurance or complete memory-reclamation certification. Historical failures remain below. No dispatcher/window/owner default or native optimization setting changes.

* Model scope and source boundary

=specs/owner_lifecycle.qnt= complements =bridge_handoff.qnt= instead of copying its queue and receiver machinery. =specs/owner_lifecycle.md= maps transitions to the actual Rust source and records lock linearization assumptions. Initialization and correct native owner execution are external preconditions; the model cannot explain an SDK setup failure or zero native root.

The host closes admission, drains native tasks, clears registry metadata and retires its executor slot and files. Initialized images remain retained. An overlapping operation may linearize before close even when it returns later. A late reply copy is not authorization to use or republish a destroyed native value. The executor slot is not every outstanding Arc or OS thread; the native test joins client threads before counting retirement.

The model checks immutable owner association at handle-use admission, no late registry publication or lazy pool recreation, accepted-work drain before join, and closed-state root/registry/file retirement. Timeout does not cancel accepted work. Closed images cannot reopen in this model. Stuttering is allowed: no eventual completion, fairness, arbitrary-native-hang recovery or unbounded leak-freedom theorem is claimed.

Runtime sources were unchanged in that model-only stage; the native repairs and their separately identified artifact are described below. Gerbil/Gambit/C native compilation and full Scheme execution remain in place. Python only drives the actual library API and observes its process; native lists/vectors, binary integers/bytes, rooted procedures and continuations carry work. JSON is diagnostic output.

=qualify_dispatch_memory.py= warms full hygienic expansion on each owner, retains three native handles per owner, rotates direct/Tokio/Rayon/Rayon-blocking, validates real Actor results and worker distribution, applies retained procedures/continuations, exercises expected Scheme exceptions and repeats DSL recovery. Namespace image counts include runtime/module images, not extra VMs. SDK heap capacity is not live data; the SDK post-GC live value is retained in its raw units. These are resource observations, not throughput A/B or dedicated-host latency certification. A two-GiB sampled RSS guard remains in place; it did not trigger these failures.

* Native diagnosis and directory repair

The optional diagnostic ABI preserves the caught Scheme exception on the original rooted-call path. It retains at most 4,096 characters, transfers the UTF-8 diagnostic as an ordinary temporary native root exactly once, and clears it before a subsequent rooted call. Successful calls keep the original native value protocol. Diagnostic encoding failures remain caught. Older images without these optional exports retain the generic rejected-root error. Initialization diagnostics separately record the failed branch, original decoded SDK status, host errno and active processor observation; unavailable diagnostics are not invented as zeroes.

The diagnostic O2 wheel reproduces the mixed-reuse failure after 16.192 seconds, owner 1, turn 288, direct mode. The actual exception is a module-read syntax error: it attempts to read a nonexistent =owner-2-modules/.../gerbil-python-ledger/scheme/core.ssi=. The same wheel rejects the fourth lifecycle startup with SDK status =-515899390=. The paired SDK header decodes facility 320, code 2: =ENOENT=. Host capture/restore and processor validation are not the failing branch in that capture.

A directory-only native control reproduces the host cwd changing into a temporary owner directory. A separate lifecycle observer records the host cwd in owner 2's module directory after work, then =getcwd= returning =ENOENT= after resource retirement, followed by SDK setup returning the same error. These are independent failures in the original execution path, not wrapper-based passes.

Inspection of the paired native image establishes the mechanism: =___os_path_normalize_directory= calls =getcwd=, =chdir= and restore =chdir= while holding an image-local pthread mutex. Each copied SDK owns a different mutex, while the process cwd is shared. Concurrent normalizers can therefore save, read and restore another owner's directory. Removing retired files then leaves a deleted process cwd, which also prevents a later SDK setup. Native root correctness alone cannot prevent this OS-global interaction.

The minimal Darwin instance adapter binds its statically linked SDK's =chdir=/=fchdir= calls to owner-thread directory operations. The minimal export list keeps those bindings local to the private image; host libc calls are not interposed. Each owner captures its initial directory before setup, and cleanup clears the private directory reference after SDK retirement. Setup failures also clear it before the owner exits. Linked single-VM execution is unchanged. No global Scheme execution lock, alternate evaluator, reduced expander, timeout relaxation or scheduler default change is introduced.

This uses Darwin's =pthread_chdir_np=/=pthread_fchdir_np= private SPI. Apple's [[https://github.com/apple-oss-distributions/libpthread/blob/main/private/pthread/private.h][maintained declaration]] describes per-thread cwd, errno behavior and clearing with descriptor -1, available since macOS 10.12. The existing private-image backend is Darwin-only; this is an explicit platform dependency, not a portable or public-POSIX guarantee. The loader must resolve those symbols; there is no fallback to process-global chdir. A native C control verifies per-thread getcwd, relative reads, failed chdir, descriptor-based restore and unchanged host cwd. Mach-O inspection confirms SDK calls bind to the image-local implementation, which is absent from the public export table.

The maintained Python backend regression uses four real owners, 1,000 directory normalizations each, Scheme current-directory parameterization and relative file reads. The independently captured unfixed control leaves the host cwd invalid even though native shutdown reports zero roots. The same control and the original 600-second reuse/eight-cycle lifecycle targets must pass on the repaired O2 artifact before admitting this repair.

The three model shell wrappers and duplicate Bash SDK-environment wrapper are removed. Quint runs through the existing Cargo test harness and Just/CI entrypoints; existing Rust native-build tests own the SDK environment boundary. No new test dependency or alternate build system is added.

* Host process-control signal regression

An early repaired-artifact reuse attempt is deliberately interrupted while advancing the source to preserve POSIX =fchdir(-1) -> EBADF= semantics. It does not finish the 600-second target. The requested SIGINT is followed by SIGSEGV (exit -11) at 209.862 process seconds, without a clean-shutdown receipt. This result is retained as a separate native failure, not relabeled as a normal stop or sustained pass.

Independent one-owner controls establish the host-signal regression: no VM produces Python =KeyboardInterrupt= and exits 0; an active VM terminates with SIGSEGV (-11); after close, SIGINT terminates the process (-2) instead of reaching Python. No Actor work or GC pressure is required. A read-only sigaction/dladdr observer finds SIGINT/SIGTERM pointing into the last private SDK image while active, and SIGINT reset to default after cleanup rather than restored to Python.

The common native boundary now saves and restores host SIGINT/SIGTERM alongside the already preserved SIGCHLD during setup, and preserves current host handlers across cleanup too. Cleanup captures the current host handler, including changes made after open. SDK-internal timer signals are unchanged: this does not disable Scheme green-thread scheduling, translate Scheme execution into Rust, cancel accepted native work or remove native Scheme exception/continuation capability.

The existing actual API suite now checks SIGINT and a custom SIGTERM handler with four live VMs, native-call recovery after delivery, a handler changed during VM lifetime, and delivery after clean close. Fresh-process baseline/live/closed controls and the original sustained workloads are separate required receipts on the final artifact. Delivery inside the SDK setup/cleanup transition and arbitrary user-installed OS signal handlers are not certified by these finite post-open/post-close tests. OS timer signal ownership and other process-global resources still require an embedding contract; same-process VM images are not crash containment.
