#+title: Data-type bulk FFI audit and scalar qualification

* Evidence boundaries

The encoder baseline remains =fc4562c91af0c8ed81840b5ceaaf40712555e0aa=.
The =scheme/utf8.ss= algorithm remains unchanged. The later rooted-object
closure regenerates SCM provenance, timestamps and hygienic identifiers;
generated byte identity is not claimed for that later receipt.
No installed SDK rebuild, kernel change, SMP admission, or Org parser
performance claim is part of this receipt.

This change adds a reusable =ScalarBatch= projection and one C leaf entry
for boolean, fixnum, character, and flonum spans. It is an actual library
API, not only a benchmark control. It batches values *within* one owner-local
request; it does not combine queued requests or enable Scheme parallelism.
The existing scalar API remains available. There is no automatic promotion
of this conversion result into a downstream parser qualification.

* Source-based implementation

The installed official =gambit.h= defines =___FIX= at line 3006, =___ORD=
at line 3060, =___F64UNBOX= for each configured representation, and
=___FLONUMP_DECL=/=___FLONUMP= at lines 3960-3989. The new entry uses these
operators rather than duplicating tag shifts, serializing values as text,
or entering a Scheme procedure separately for every element.

The complete input is classified before publishing any C output. The leaf
entry neither allocates Scheme objects nor retains Scheme body pointers.
Rust checks owner/provenance, copies machine words into reusable scratch,
and decodes a representation-stable 16-byte projection. It validates all
payloads before replacing caller output. A reusable batch retains no Scheme
handle after return; its retained payload bits are owned scalar data.
The raw ABI requires live owner-local objects and disjoint spans. It does
not make arbitrary machine words safe, establish GC roots for borrowed
objects, or authorize calls from another thread.

Fixnum zero (=___FIX(0)=) is a Scheme word, not a null pointer. The original
scalar receipt did not close safe borrowed-word zero. The subsequent
[[file:bridge-rooted-objects-20261011.org][rooted-object qualification]] replaces
that word representation, accepts trusted zero exports and preserves
fail-closed untrusted raw constructors. Registry tokens remain positive.

* Data-family audit

| Family | Existing transport and ownership | Audit outcome |
|--------+----------------------------------+---------------|
| bool/fixnum/char/flonum | Borrowed Scheme exports; per-value scalar FFI | Single-entry scalar spans; trusted zero and strongly rooted scalar projections covered by the later receipt |
| String/UTF-8 | Rooted strings, owned validated Rust bytes/strings | Existing whole-value path; encoder baseline untouched |
| bytevector/Vec<u8> | Root ID lifetime, whole-copy into slice or reused Vec | Existing bulk path, no borrowed heap pointer escapes; growth/shrink/empty/error/unaligned tests exist |
| exact integer | Rooted IDs, indexed snapshot references and checked machine projections | Canonical signed binary magnitude construction/copy, short fixnum and limb paths, GC and error-preserving output tests; no decimal coercion or truncation |
| symbol/keyword | Handle-backed borrowed views | Not an owned bulk string/interning transport; missing qualification |
| pair/proper list | Strongly rooted creation and shallow snapshots | One complete snapshot root; nested/false/zero elements, parent release and GC covered; pair exposes car/cdr, not arbitrary improper-list sequence flattening |
| generic vector | Strongly rooted creation and shallow snapshots | One native snapshot/root rather than per-element roots or Rust token buffers; element borrows cannot outlive the snapshot |
| u16/u32/u64/f32/f64 homogeneous vectors | Sealed native-element whole-span transport | Rooted construction, transactional reused copy, indexed snapshot lifetime, bit-pattern and GC contracts; see numeric-vector receipt |
| signed homogeneous vectors | No qualified safe bulk family yet | Remain a separate representation/coverage gap; not inferred from unsigned vectors |
| rational/complex/hash table | No complete safe owned bulk transport found | Missing representation and ownership semantics; not coerced to text or f64 |

The audit does not claim every Gerbil data structure is already implemented.
Collection elements can contain GC-managed objects; a scalar bit-copy API
cannot be reused as their ownership protocol.

* Correctness and anti-regression gates

=just bridge-types-contracts= exercises ABI layout and native owner tests.
Scalar coverage includes boolean false/true, ASCII/BMP/supplementary chars,
finite floats, NaN payload bits, infinities and negative-zero bits. Repeated
calls verify stable scratch capacity. Empty spans, null nonempty spans,
raw fixnum zero, unsupported types, untrusted provenance and unchanged
output on failure are checked. Existing tests retain exact-integer sign/
overflow, root single-release, byte-copy growth/shrink, invalid UTF-8 and
callback panic containment.

The dev-only syn regression gate requires exactly one bulk foreign entry
and no per-element scalar projections in =scalar_batch.rs=. Negative
controls inject both a scalar method loop and a substituted scalar ABI.
It does not forbid ordinary Rust loops that classify owned scalar payloads.

* Matched results

=just bridge-types-matched= runs five families, three loads, 20 batches per
variant, ten ABBA groups: 600 batches, 22,200,000 requests, eight values per
request. Five prebuilt rows rotate across requests, including the character
and floating-point distributions above; the fixnum fixture is 42. Full
integer-range correctness is covered separately, not inferred from that
fixture's performance. Both variants use the same runtime owner, input,
reused output, timer and correctness checks. P95/P99 are exact nearest-rank
percentiles of individual requests, pooled over all 20 batches, not
percentiles of 20 batch means. Timer overhead is included, not corrected.
The approximately 42 ns quantization limits interpretation of tiny times.

All 15 family/load gates passed: total timed wall, pooled P95 and pooled
P99 each improved over the existing per-item scalar control. The result
admits the new opt-in scalar span API locally; it does not replace the
frozen UTF-8 baseline or qualify Tokio response tails.

The bulk batch reserves 192 additional Rust bytes for eight values
(64 handle bytes + 128 projection bytes); both variants reserve 128 bytes
for caller output. No shrink-per-request policy is imposed. Percentile
observation storage alone reserves 328,000 / 3,280,000 / 32,800,000 bytes
for the three loads, identically for both variants. These figures are
capacity accounting, not allocator metadata, allocation counts, per-mode
RSS or GC measurements. Initial warm/compile-adjacent results are retained
separately and are not the final receipt.

* Scheduling boundary and remaining work

Official Tokio 1.53.1 =oneshot.rs:1299-1315= publishes completion and wakes
the waiting task. =worker.rs:1341-1366= routes an external Scheme owner's
wake to remote injection; =worker.rs:1420-1427= locks =shared.synced= and
pushes the task. This verifies a potential contention path, not a measured
lock duration. Handoff timing includes publication, synchronization, wake,
and runnable-task waiting. It must not be labeled as mutex contention alone.

The prior full scheduling receipt remains
[[file:bridge-utf8-tokio-scheduling-audit-20261011.org]]. It isolates long
handoff intervals and low-owner-CPU service stalls, but cannot quantitatively
split injection mutex wait from runnable delay. No new scheduling speedup
is claimed here. Rejected recv-many and response-channel candidates stay
reverted. Batching scalar fields within one payload removes repeated FFI
entry, not request admission or response wakeups. SMP remains unqualified.
