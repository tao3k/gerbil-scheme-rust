* Missing native lowering contract
The frozen Actor compilation used:
#+begin_example
-O2 -U___SINGLE_HOST -U___INLINE_JUMPS -D___MULTIPLE_HOSTS -D___DONT_INLINE_JUMPS
#+end_example
The initial migration used SINGLE_HOST_LIMIT=1 and retained inline jumps.
Compiling the SAME generated C with the frozen lowering reduced the static
instruction counts for input construction, native business unit, and service
handler to the frozen counts (696, 2174, 480). The scheduled driver is 5268
instructions versus 5620 frozen and 7534 under the partial lowering.
These counts include cold paths and are not executed-cycle measurements.
The repair is limited to explicitly declared SeparateProcedures modules;
normal-module GCC safeguards and O2 remain unchanged.

* Decision and retained counterexamples
The original control was anomalous, so the migrated image's performance arm
was STOPPED. No candidate gain or recovered 4.513 ms is claimed. The earlier
41.023 ms partial-lowering result is retained as failed evidence, not a new
baseline. The original 4.513 ms itself did not pass the 128 backlog gate.

Metadata-only commits do not migrate a measured implementation. Static source
or code-size parity and passing semantics cannot waive an anomalous control.
These obligations are added to the existing construction-contract QNT gate.
The cause of the earlier same-byte timing variation remains unknown.

* Four-round replay on the persistent 7F checkout
The original reader and VM image produced 8.331, 7.817, 5.951 and 3.927 ms
p99 in execution order. Each round completed all one million messages with
zero rejections, errors or timeouts and a clean shutdown. The fourth round
reached the 4.513 ms research reference. Its p99.9 was 4.265 ms and peak
backlog was 4,329. All four rounds exceeded the original 128 backlog gate.
The freshly linked PR image has functional validation. The four performance
observations belong to the original frozen artifacts and keep their original
native acceptance failures.
