* One receipt per semantic transition

The prior protocol carried normal/report flags through dynamic-wind, then
credited whole work and diagnostics at unwind. Sliced work already accrued to
the current lease. The new protocol aligns those ownership boundaries:

| Transition | Authority and update | Never implied |
|------------+----------------------+---------------|
| First plan selection | Invocation freezes descriptor; Scheme reports one selected plan | A completed computation |
| Successful whole return | Epoch checked; private return site inherits acquired owner/class; declaration accrues to lease | Root retirement, result delivery, instruction count |
| Sliced checkpoint | Existing bounded checkpoint accrues actual reported work | Credit for an unreported suffix |
| Nested unit exit | Existing lease depth decreases; accumulated work remains owned by outer lease | Another flush or another success credit |
| Outer release / suspension | Existing lease flush transfers accumulated work to its class total and resets accumulator | Admission capacity release |
| Exceptional or continuation escape | Wind exit releases lease; no successful-return credit site reached | Rollback of completed nested or checkpoint work |
| Reentry | Reacquire lease; retain original immutable plan | A new selection report or replacement-epoch authority |

Each multishot successful return charges its retained declaration again. This is
conservative logical work, not exact partial-replay CPU accounting. A subsequent
exceptional replay cannot inherit success: no normal-return flag exists. Old
policy returns/checkpoints remain inert under the policy identity fence. An old
48-record continuation does not become compliant with a new four-record bound.

Invocation state retains only its first descriptor. It is not pooled, and the
three wind callbacks remain. Public layout validation, cold metadata publication,
class permission invalidation and complete Scheme continuations/actors/GC stay
intact. Whole-return accrual executes before wind exit while the Scheme lease is
still owned; a suspended nested invocation first settles the lease through the
existing suspension boundary, then restores its depth on reacquisition.

Selection reports now describe first selection, including escaped unfinished
invocations, rather than waiting for first unwind. Successful work is visible in
the existing work snapshot as accrued plus settled work. Final idle counts retain
the same conservation contract. Reporting cannot retire native roots or capacity.

This changes the accounting protocol, not a threshold. It can add an accumulator
write on whole-return paths; fewer flags are not assumed to outweigh that cost.
Existing per-unit lease acquisition/release remains, so this candidate does not
claim to eliminate all service-cycle locking or explain every latency spike.

* Architectural consequence before another candidate

The actual path still enters a separate work-layout dynamic-wind and obtains /
releases a Scheme lease for each of 8256 declared units. The Actor executor also
has its own item-progress publication, quantum boundary, coordinator acknowledgement
and service completion transition. Moving credit ownership alone did not merge
those execution lifetimes or remove those independent boundaries. This is a
source-level structural observation, not attribution of the measured p99.

The next design question is a Scheme-owned execution extent for an Actor turn:
can item invocations borrow its lease and immutable plan, with suspension at
existing Actor/cooperative boundaries, while standalone short invocations retain
their own extent? Before implementation, the existing model must make borrowed
extent ownership, remaining work, scheduler-boundary release, multishot reentry
after turn completion and per-result retirement explicit. A batch cannot simply
hold a lease across an existing yield, which would prevent a competing short
Scheme thread from obtaining it; nor can eight 48-record items become one
uninterruptible declaration. No such fusion is implemented or claimed here.

This changes the granularity of the scheduling contract, rather than relocating
the same counter again or relaxing a threshold. The current candidate remains
unaccepted and defaults unchanged. Rust must continue to dispatch only across
instances; Scheme owns all internal execution, suspension and reentry.
