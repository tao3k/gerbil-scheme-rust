#+title: Completion opportunity custody and coalesced retirement
#+options: toc:nil num:nil

* Architectural decision from the accumulated evidence

The previous reports establish distinct boundaries, not a sequence of admitted
speedups. [[file:30.58-capacity-backed-peer-delivery.org][30.58]], [[file:30.59-revocable-offer-native-entry.org][30.59]] and [[file:30.60-dedicated-offer-ports.org][30.60]] separate Rust offers from native admission;
[[file:30.61-scheme-completion-handoff.org][30.61]] establishes real late short admission before Scheme successor selection,
but its explicit handoff candidates fail throughput/tail admission. There is no
basis for promoting them by choosing a favorable workload or percentage.

| Plane | Authority | Required invariant |
|-------+-----------+--------------------|
| Unentered input | Rust pool/owner claim protocol | Revocable owned input; no Scheme roots or sleeping native credits |
| Entered execution | Complete owner-local Scheme runtime | Actors, green threads, GC and continuations stay on that VM |
| Completion opportunity | Scheme publication epoch | Acknowledging old work cannot erase a later publication |
| Ready result custody | One fixed-owner token | Every handed ID remains rooted until native take/projection |
| Resource retirement | Existing per-result native permit | Projection/root balance returns this result's credit immediately |

Queue separation alone cannot isolate shared VM CPU, GC or synchronous foreign
calls. Conversely, making every completed bulk graph yield to Rust adds crossings
without creating more Scheme execution capacity. The architectural correction is
to coalesce completion opportunities while keeping result custody and resource
retirement independent. No timer, yield count, larger input window or changed
runtime default is used as a substitute for this ownership protocol.

Rust continues to distribute across fixed owners. Scheme retains the complete
native language/runtime, Actor scheduler, green threads, continuations, native
types, exceptions and GC. No Scheme translation or SMP change is introduced.

* Explicit CoalescedHandoff API and native protocol

The experimental library policy is =SchemeServiceCompletion::CoalescedHandoff=,
configured on an idle native service by the existing completion-policy API.
Snapshot remains the default; FairHandoff remains an unpromoted historical
control. Service ABI v8 adds epoch envelopes, acknowledgement and typed readback.
Older endpoints reject the new policy instead of inferring support from a host
executor name.

- On the first outstanding completion, Scheme publishes a new epoch and an owner
  opportunity. If an eligible successor exists it yields before selecting that
  successor; otherwise the worker's existing blocking receive is the handoff.
- Further bulk completions share the outstanding opportunity. The first newly
  ready short result can publish a newer epoch even while bulk custody remains
  outstanding. Scheme's existing FIFO, class budget and Actor-lane rules apply.
- A harvest returns at most one ready short ID and the current bulk snapshot.
  Native jobs remain in Scheme's existing job table. Each job's typed claimed
  epoch plus an aggregate count records custody; no parallel ID registry or
  duplicate per-result hash lookup is added. A second harvest cannot overwrite a live token.
- Rust holds a non-Clone token borrowing the exact native image. Its zero-sized
  owner marker forbids Send/Sync. The token contains metadata, not Scheme objects.
  Each result is taken and projected through the existing native type API, and
  its permit returns immediately before any later application projector runs.
- After the entire snapshot is projected, Rust retains only acknowledgement
  custody. The next advance consumes the token and piggybacks its acknowledgement
  before acquiring another snapshot. It does not add a separate crossing per bulk
  result or defer any resource return. The owner cannot park or skip an advance
  merely because its job map is empty while this token remains outstanding.
- An acknowledgement consumes its matching token only after all claimed IDs have
  been taken. It clears the opportunity only if the epoch is still current and
  both native ready queues are empty. A later publication or stale/duplicate
  acknowledgement cannot clear another token or lose a ready opportunity.
  If acknowledgement leaves ready graphs in its current epoch, carry them to a
  fresh epoch before another harvest. Reusing that consumed epoch would let a
  delayed duplicate acknowledgement consume a later fully projected token.

Cancellation and observation timeout preserve entered graphs and claimed roots.
Normal close drains accepted work, consumes pending custody, joins Scheme workers
and retires roots. Error drain retains the existing native cleanup/quarantine
rules; dropping a Rust metadata token is not authority to free a Scheme graph.
Epochs do not wrap or reset across idle policy switches. Exhaustion is rejected.

The typed =scheme_service_completion_on= readback reports actual policy, epoch,
token custody, claimed/queued counts and native batch/result counters. Benchmark
reads occur outside timing and assert no pending custody after each sample. A
progress-aware maximum reply includes both epoch and progress headers plus the
full 65536-job identity bound. Readiness receipts never release capacity.

This establishes scheduling opportunities and custody, not preemption of an
arbitrary synchronous constructor, projector or foreign function. Coalesced
snapshots remain bounded by the existing native capacity. No universal p99 or
arbitrary-owner fairness theorem follows from a finite model.

* Existing model refinement and native controls

The existing service_sharing model now tracks per-owner publication epochs,
claimed epochs, outstanding opportunities and harvested identities. Its original
root, capacity, execution, cancellation and lifecycle transitions are reused.
Only ready-token custody can be deferred; project still uses the original
per-result completion/credit transition.

New scenarios demonstrate multiple bulk IDs under one token, capacity return
before a later result is projected, a new short epoch while an old token is held,
old/duplicate acknowledgement, observation timeout and close drain. A mutation
that clears a newer opportunity with an older token must violate safety. Existing
unbounded-class-harvest mutations remain required. Additional finite domain
bindings put both bulk identities on one owner; no second scheduler model is
created. Epochs are bounded to two publications, including ready carry, for sampling, so this is not an
unbounded liveness proof.

The initial targeted gate passes in 67.18 seconds: original completion cases in two
existing domains, coalesced cases in two finite instantiations, sampled traces of
1000 x 64 steps per domain/init, and required mutation counterexamples. After adding fresh carry epochs, the
expanded targeted gate passes in 64.22 seconds, including duplicate old ack after
a later token is fully projected. Epoch and harvest counts are distinct: several
publications can coalesce before a harvest, but a consumed token epoch cannot be
issued again. The first
scope-binding/typecheck failure is retained; existing root/capacity assertions remain. The one-bulk bound continues to apply
only to FairHandoff; CoalescedHandoff explicitly permits a capacity-bounded bulk
snapshot while requiring linear epoch custody.

Native controls cover all three policies, actual late-short ordering, active
policy-switch rejection, GC/continuations/exceptions and close drain. A real
Scheme fixture releases three latched batches and drives them until all three
are ready without harvesting on Rust's behalf. The real library must recover
three results using one token, project them normally, consume acknowledgement,
and report no claimed/queued graph or pending opportunity. Before harvest the fixture
also attempts a raw take of a genuinely ready graph: two absent -1 sentinels
cannot authorize custody. It must reject the take without changing the three
queued graphs. This closes a concrete native implementation gap that the abstract
harvest precondition alone did not expose. Shared-short controls
exercise unentered cancellation, accepted observation timeout and closing drain
with CoalescedHandoff enabled. A second actual endpoint control submits two native typed short jobs, leaves both
ready before harvest, takes one per bounded harvest, and injects the first token's
acknowledgement after the second token is fully projected. The second token must
remain owned until its own acknowledgement, then drain with zero queued/claimed
graphs. Final gate results are recorded below.

* Direction: one native owner service cycle

This protocol coalesces ready identity custody and scheduling handoffs. It does
not yet batch native take/projection: Pump::collect still invokes Job::complete
and the rooted native command for each result. Arbitrary user projection also
runs synchronously on the owner before the next short claim/supply turn. Thus a
larger ready snapshot can reduce handoff count while lengthening the interval
before input admission. These are current code boundaries, not an attribution
of an observed OS or GC spike.

The next architectural unit should be one owner-local service cycle joining
Scheme execution progress, bounded ready transfer, result retirement and fresh
input opportunity. Its batch result interface needs individually releasable
native roots; simply retaining an aggregate Scheme vector until the last
projector finishes would delay reclamation and defeat per-result credit return.
The existing typed request/project API and affine Scheme state must survive that
change. Complete/probe timing remains distinct from client resumption.

The admission condition is joint: preserve throughput, bound short waiting and
avoid reducing actual owner progress. Fewer notifications or successful finite
traces alone do not satisfy it. Do not continue tuning yield thresholds or expand
the executor matrix before resolving this service-cycle ownership boundary.

controls pass 2/2; final Clippy passes with warnings denied (31.69 seconds). Native
contract tests pass 3/3 in 14.84 seconds, including the real sentinel/carry controls,
then the dedicated watchdog control passes 1/1 in 5.01 seconds. Default libtest

These local receipts do not declare new-head remote CI green.

The final frozen capture exits 0 in 6.48 seconds without controller timeout.
All 40 samples pass workload/policy checks: 8192 orders, 64 short probes, four

Decision: NOT PROMOTED. The mixed throughput gain (+0.85%) does not offset CPU
throughput loss (-2.56%), CPU short p99 (+39.51%), mixed short p99 (+1.27%), bulk
mixed p99 (+4.05%) and owner finish spread regressions in both loads. Coalescing
works as a custody protocol but does not establish a joint performance improvement.
Snapshot and all existing runtime defaults remain unchanged.
