#+TITLE: Scheme service checkpoints follow actual first-execution debt
#+OPTIONS: toc:2

* Evidence and status

Unpublished ABI25 candidate, with unchanged defaults and ABI23 as the matched
control. The rejected private-notification ABI24 experiment remains frozen;
see [[file:30.80-scheme-directed-grant-wake.org]]. ABI25 uses the existing shared
broadcast policy rather than combining that experiment with this change.

Source review found a remaining progress-contract split. ABI23 retains work
execution debt through runnable/registration until the first receiving grant,
but =service-checkpoint!= only consults the separate dispatch ledger. A worker
can acknowledge dispatch before registering for execution. At that point the
service cycle stops offering a dispatch checkpoint even while execution debt
is still outstanding. This is a source-established guarantee gap, not a unique
attribution of every measured tail.

* Unified service progress contract

| Event | Dispatch ledger | First-execution ledger | Checkpoint eligibility |
|-------+-----------------+------------------------+------------------------|
| Accepted native short | Pending | Pending | Eligible |
| Scheme worker starts | Acknowledged | Still pending | Remains eligible |
| Worker registers | Unchanged | Still pending | Remains eligible |
| Receiving first managed grant | Unchanged | Acknowledged exactly once | No longer eligible on this debt |
| Validation/terminal exception without grant | Unchanged | Distinct ungranted terminal receipt | No longer eligible on this debt |
| Later handler computation or suspension | Unchanged | Already settled | Does not hold this checkpoint open |

The Scheme service boundary yields once when joint progress is enabled, either
ledger owes progress, and there is no ready short result to collect. This
leaves completion collection ahead of more scheduling opportunities. Each
native boundary has at most one such opportunity. It does not synchronously
wait for a handler or first grant, acquire an outer execution lease, block all
bulk input, or turn a batch into an uninterruptible unit. A later boundary can
offer another opportunity if debt remains. Actual service call and cooperative
work durations are not wall-clock preemption guarantees for arbitrary Scheme.

The execution-debt predicate is opt-in. It observes the same Scheme work epoch
under the existing budget mutex. Policy reconfiguration requires an idle native
service, so the epoch cannot change during active work. No service callback
runs while holding that mutex. Checkpoints remain outside the service mutex,
preserving service-to-budget lock order. The checkpoint flag is immutable epoch metadata; both arms normalize to the
same registered layout mode. There is no new handler-level check, lease, event
registry or replay allocation. Uncontended service boundaries still
pay the policy predicate's branch cost; performance admission must measure it.

Receiving-thread acknowledgement and exception/ungranted settlement retain
ABI23 ownership. Continuation replay does not issue another first-execution
receipt. Rust owns cross-instance dispatch; Scheme retains Actors, green
threads, continuation and GC execution. Observer cancellation/timeout cannot
settle accepted native execution or release its roots early. Close retains
progress debt until normal completion or ungranted terminal drain.

* Reused Runtime model and actual API

The existing joint service-cycle model now has an execution-checkpoint policy:
its opportunity predicate consults dispatch or actual execution debt. Legacy
controls retain dispatch-only behavior. New directed controls cover the gap
after dispatch acknowledgement, a repeated opportunity that cannot consume
debt, eligibility ending at grant before handler completion, abandoned/closing
ungranted drain, and a mutation that skips the opportunity before collecting a
ready bulk result. Native qualification reuses the existing registered grant,
GC, continuation replay, exception and Actor controls, with the new predicate
checked before and after actual first grant.

The Rust owner API is
=configure_scheme_service_execution_checkpoint_plan_on=; native ABI25 configures
Scheme's policy. Both arms retain native type projection, specialized layout
plans, class fairness and identical logical work bounds. No JSON or Rust
implementation replaces Scheme computation.

The candidate is not admitted for publication: actual short tails improved in
this capture, but owner completion fairness and mixed scheduled short tails
remain open. Neither statistical significance nor release-wide improvement is
claimed from these small matched windows. The full unpublished-stack versus
published-control gate is not promoted. Preserve the positive and negative
results, keep defaults unchanged and do not rerun an unchanged candidate to
seek a favorable window. Further protocol work must distinguish opportunity,
actual useful execution and completion progress rather than equating extra
checkpoint eligibility with useful progress. The original historical watchdog
failure still lacks same-failure attribution; successful current runs do not
close it.
