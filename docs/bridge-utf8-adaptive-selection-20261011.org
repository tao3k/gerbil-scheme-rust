#+TITLE: Adaptive UTF-8 selection: complete cross-corpus rejection

* Identity and selection algorithms

Production and generated SCM return exactly to =fc4562c=; PR #18 remains at
=520a2423fbc6296e46d2f34904036722169f2a31=. No kernel, SDK, acceptance limit,
Rust reserve policy, public ABI or SMP capability is changed.

Official local Gambit =lib/c_intf.c:1270-1360= dispatches bounded stream encoders;
=lib/gambit/string/string.scm:560-669= determines width before choosing ASCII
copying or multibyte emission. These motivate two actual source experiments,
not a claim that upstream implements our selectors:

- First-character selection chooses the existing ASCII-first or partitioned
  tree per current 256-character leaf. Direct emission preserves each tree's
  scalar checks. Prefixes are deliberately not assumed representative.
- Complete-leaf selection reads every current scalar, OR-reduces width bits
  and selects ASCII, two-byte, BMP or general emission. Power-of-two bounds on
  the OR are conservative width proofs, not an estimate of average density.
  A fresh local =___C[256]= span prevents classification/emission disagreement.
  Storage is at most 1 KiB per active C leaf, never a retained string/encoding
  cache. It is removed on rollback. All scalars are still encoded each request.

Both preserve pointer tags, capacity/type checks, scalar rejection, 256-scalar
polling and full Rust UTF-8 validation. No per-character foreign call is added.

AOT runtime, runs full contracts once and aggregates failures only at the end.
