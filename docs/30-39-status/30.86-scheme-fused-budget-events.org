#+TITLE: Scheme event publication inside existing budget transactions
#+OPTIONS: toc:2

* Decision and scope

The repaired but performance-rejected ABI31 experiment is retained in
[[file:30.85-scheme-budget-owned-runtime.org]]. Its paired throughput regressed
for both CPU and mixed loads. Favorable pooled numbers did not qualify it.
This revision changes event transaction boundaries before timing another image;
it does not tune yield thresholds or repeat an unchanged candidate.

=SchemeServiceCyclePolicy::RuntimeEvent= remains the actual opt-in Rust API
through =configure_scheme_service_boundary_plan_on=. Its ABI and native type
contract are unchanged. Scheme owns execution, scheduling, Actor turns, green
threads, GC, continuations and exceptions. Rust dispatches across instances and
projects each result on its fixed owner. No default setting is changed.

* Transaction ownership

| Event | Previous critical sections | Revised critical sections | Preserved authority |
|-------+----------------------------+---------------------------+---------------------|
| Managed short submission | Context registration plus work publication: 2 | 1 existing work/cache transaction | Pending execution is not a received grant |
| Actor publication with four active children | 4 independent registrations | 1 bounded registration transaction | Four independent context tokens, before mailbox delivery |
| Held lease suspends | Release plus phase publication: 2 | 1 existing release transaction | Full nesting is saved; selected peer is not yet received |
| Held lease resumes | Phase restore plus acquire: 2 | 1 existing receiving transaction | Actual wait/receive and nesting restored before user suffix |
| Runnable yield with no lease and phase already eligible | 2 no-op phase transactions | 0 | The existing Scheme yield still executes |
| External wait without held lease | One transaction per phase change | Unchanged | Suspension remains distinct from runnable work |
| Context entry / terminal unwind | One per dynamic event | Unchanged | Index and entered/retired totals publish together |

These counts come from the selected source paths, not measured CPU attribution.
The unobserved ready-first control also receives the fused suspension path;
there is no intentionally slower control. Old mirrored experimental policies
retain their existing implementation for semantic controls.

The release body is a fixed structural macro shared by ordinary release and
suspension. It adds no per-handler callback, phase test or second lease record.
The receiving function is generated from the existing acquisition body with
resume-specific publication; ordinary handler specializations remain free of
Runtime acquisition/release bookkeeping. A blocked receiver still updates only
at actual block/resume, using existing queues and grant ownership.

Short job publication now creates its token in the existing pending-work/cache
transaction before sending the job. Bulk context registration remains a
necessary independent event where no pending-short transaction exists. Actor
registration batches only metadata for the producer's already-bounded active
children, not user execution. It never makes the batch uninterruptible.

* Continuation and exception boundary

Dynamic entry and exit still update the context index and phase counts under
the existing budget mutex. Retirement is not postponed to job collection or
Actor reply; continuation escape and exceptional exit must release that dynamic
extent immediately. Reentry reinstates the retained context's epoch and its
original declared work bound. Stale epoch events cannot update a new ledger.

A held suspension releases the entire saved nesting and publishes suspension
before granting peers, under one mutex acquisition. Resume publishes eligibility
inside the receiving transaction; actual blocking remains lease wait until the
owner check succeeds. Original nesting is restored before the user suffix runs.
Every user thunk, external wait and Scheme scheduler yield runs outside the
mutex. Lock order remains service then budget; no budget transaction takes a
service lock, waits for a user computation or transfers a root/capacity permit.

The existing independent completion, cancellation, timeout and close protocols
remain. A caller timeout cannot retire already-accepted Scheme work, and an
individual result retains its own root and capacity retirement.

* Model and native checks

The existing joint Tokio/fixed-owner/Actor/green-thread model reuses its dispatch,
waiter, CPU lease, blocking, Actor child phases and activation stack/index.
New witnesses check fused short publication without an execution acknowledgement,
both children published before Actor execution, external release/resume across
cancel/close with roots retained, and a required suspended-owner mutation.
Existing split-index-retirement, stale-epoch, multishot and exception controls
remain. There is no new lease or waiting-queue model.

Typecheck and 104 directed cases across both completion domains pass, as do
400 cross-layer random samples of up to 64 steps, seed 42. Model source SHA256:
=00e534c8b8e92d61f729aeeaf8225431b1af52689a9bac4da0b246c9dfc87cfc=.
These finite checks do not establish native timing or universal liveness.

The new real Scheme fixture escapes from inside an external suspension nested
under two budget extents, reenters normally, forces GC, then reenters with an
exception. It checks external/owned snapshots, restored outer ownership and
zero terminal phases with entered/retired conservation. Actual typed API tests
also cover initialization failures, close/cancellation/timeout drain and
first-grant ownership. Strict Clippy passes. The three native tests pass in
31.15 seconds, four owners joined, roots zero, files removed, FD return and
native close 2.59 ms. The five-second meaningful-progress watchdog is unchanged.

* Complete net-cost result: rejected

=service-runtime-fused-v31-r1= completed all 40 windows in 8.04 seconds,
exit 0, empty stderr, unchanged compiled host/image/source identities, no
controller timeout and empty compiler boundaries. Native image SHA256:
=9fde369b90e7354413c1cc4d90ad8d6d5223254c14e8bc11a7580e4c1f8775c5=.
Compiler checks at the boundaries do not establish absence of other OS work.

Every window preserves 8192 orders, 64 short probes, exact declared work,
first grants and 1088 results. The observed candidate enters/retires 5184

* Next architectural question

Three concrete transaction fusions have not established a net gain. Further
coalescing must not become the default response. Audit which eligibility facts
are already owned by budget queues, receiving grants, Actor mailboxes and the
native Scheme runnable/blocked scheduler, and whether cold diagnostic progress
can be separated from scheduling authority. The current event path still owns
per-job/per-turn activation tracking; that is a source fact, not a measured
exclusive cause of the loss. A future replacement needs the existing joint
model, actual API wiring and a new net-cost gate.

Do not recover throughput by postponing dynamic-wind retirement, recycling
mutable continuation-owned tokens, hiding exceptional exits, weakening Scheme
execution or changing default policy. Retain independent completion roots and
capacity. The historical watchdog attribution gap remains open independently
of the current bounded native acceptance.
